# DART BIG:IN — 원격 MySQL 기반 로컬 서비스

재무 수치·공시 청크·BGE-M3 벡터는 .env에 지정된 원격 MySQL에서 읽습니다. 로컬에서 질문을 BGE-M3로 임베딩하고 NumPy로 유사도를 계산한 다음, 선택된 근거를 Gemini에 전달합니다. 원천 데이터 전처리와 DB 적재는 데이터 담당자가 수행합니다.

## 폴더 구성

| 경로 | 역할 |
| --- | --- |
| app.py | 로컬 웹 서버와 API 진입점 |
| snapdart/ | 분석·검색·시세 명령, Gemini 요청, 화면 데이터 구성 |
| dart_remote/ | MySQL 조회, 벡터 검증·검색, 출처 조회, 결과 저장 |
| config/sectors.json | 산업별 표시 순서·검색 주제·용어 설정 |
| web/ | 현재 산업·기업 화면, 그래프, 출처 창과 글꼴 |
| data/krx_api/ | KRX 지수 수집 캐시 |
| data/service/market.json | 시세 수집 결과 |
| data/service/remote/ | 현재 게시 보고서·시세·Gemini 응답 캐시·사용량 기록 |
| .dart_cache/ | 원격 DB 벡터의 검증된 로컬 검색 캐시 |
| scripts/, tests/ | 실행 점검과 현재 기능 검증 |
| notes/ | 이전 보존 요청이 적용된 문서·설치 목록. 실행에 사용하지 않음 |
| deploy/ | 배포 패키지. 이번 정리에서 변경하지 않음 |
| docs/ | 현재 기능 설명은 [4차구상/README.md](docs/4차구상/README.md); 이전 설계는 N차구상·history에서 보존 |

.env와 Python 가상환경 .venv는 유지합니다. 과거 SQLite DB·XML 원본·별도 검색 서버·팀원 예제·이전 화면 코드는 삭제했습니다. 로컬 서비스는 deploy 폴더의 코드에 의존하지 않습니다.

## 서비스 실행

프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
& .\.venv\Scripts\python.exe -X utf8 app.py --no-market-refresh
```

브라우저에서 http://127.0.0.1:8501을 엽니다. 실행 시 시세를 갱신하려면 --no-market-refresh를 생략합니다. 저장 보고서가 있어도 데이터 버전과 출처 확인을 위해 원격 DB 연결이 필요합니다.

새 PC에서는 Python 3.12 환경을 준비합니다.

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
```

.env에 MySQL 접속 정보, SEARCH_BACKEND=numpy, GEMINI_API_KEY, GEMINI_MODEL을 설정합니다. BGE-M3 모델은 최초 사용 시 다운로드합니다. KRX_API는 지수 수집, OpenDART 키는 최근 공시 목록 갱신에 사용합니다. 키와 비밀번호는 Git에 올리지 않습니다.

## 분석·검색·시세 갱신

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m snapdart.analyze --llm --sector 반도체
& .\.venv\Scripts\python.exe -X utf8 -m snapdart.query --sector 반도체 --company SK하이닉스 --year 2025 --report-type FY --intent hybrid --question "HBM 수요와 투자 변화"
& .\.venv\Scripts\python.exe -X utf8 -m snapdart.market
```

--llm은 동일 입력의 Gemini 캐시를 재사용합니다. --refresh-llm은 다시 생성합니다. --offline은 Gemini 없이 원격 DB 근거를 발췌하며 게시 보고서를 교체하므로 기존 AI 결과를 유지하려면 웹 서버만 실행하세요.

MySQL의 현재 검증된 버전과 기업·기간 조건으로 청크를 조회하고, 질문 벡터와 저장 벡터의 코사인 유사도로 상위 근거를 선택합니다. 재무 수치는 표준화된 재무 뷰에서 별도로 읽습니다. 모델·차원·버전·청크 일치 여부를 검증하며 원격 DB에는 쓰지 않습니다. keyword는 명시적으로 선택하는 키워드 검색 모드입니다. 별도 검색 서버나 FAISS 원본 파일은 필요하지 않습니다.

인사이트는 문장별 자연어 공시 출처를 유지합니다. 입력 ID와 인용 위치, 적격 근거 최소 1개 및 평가 조건을 검사합니다. 현재 프롬프트와 검증 과정은 [4차구상 기능 설명](docs/4차구상/03_인사이트생성과프롬프트.md), 이전 설계는 docs/3차구상/프롬프트 정의서.pdf를 참고합니다.

출처 창은 MySQL의 공시 문구·재무 수치와 DART 원문 링크를 표시합니다. XML 원본을 삭제했으므로 전체 표의 행·열·병합 셀 형태를 로컬에서 복원하지 않습니다. DB에 없는 표 구조를 임의로 만들지 않습니다.

## 서비스 연결 — 2026-10-07

현재 로컬·배포 서비스는 `dart_remote.wordcloud.apply`를 통해 이 점수 계산기를 사용합니다. 원격 MySQL의 현재 검증된 버전에서 Q1/H1/Q3/FY 청크를 읽고 사업의 내용·경영진단·연구개발실적을 분석합니다. 기타 참고사항은 해당 사업 섹션에 있으면 포함합니다. 같은 청크 안의 반복은 한 번으로 집계합니다.

산업 화면은 KRX 비중 순 상위 5개 운영 기업을 대상으로 합니다. 비중이 없으면 기업 코드로 순서를 고정합니다. 화면에서 선택한 기업·연도 범위를 벗어나지 않습니다. 지정한 전체 분석 기간을 사용하며 누락된 자료를 0으로 대체하지 않습니다.

최신 연도 키워드는 현재 언급 점수 50% + 변화 점수 30% + 확산 점수 20%에서 기업 집중 감점과 일반 경영 표현 2점 감점을 뺀 순위 상위 12개입니다. 최신 등장 청크 2개·기업 2개 조건을 유지합니다. 기업 화면은 해당 기업만 분석하므로 등장 기업 조건을 1개로 바꾸고 집중 감점은 적용하지 않습니다. 확산 점수는 해당 기업에 존재하면 100점으로 일정하여 기업 내 순위에 영향을 주지 않습니다. 이 기업용 확장은 산업용 확정 명세와 구분됩니다.

최종 신호 점수 순으로 Top 12를 선택한 뒤, Python이 만든 시각화 가중치 `display_weight`(30-100)를 글자 크기에 사용합니다. 화면에서는 이 값을 다시 정규화하지 않으며 LLM 중요도라고 표시하지 않습니다. 🔥는 변화 점수 90점 이상이고 변화량이 양수인 별도 상승 표시입니다. 🔥는 `is_hot=true`인 단어에만 작은 별도 표시로 붙습니다. 클릭하면 저장된 Gemini 용어 설명·간접 인용·출처를 표시합니다. 점수 구성과 선정 이유는 고객에게 표시하지 않습니다. 새 키워드의 설명은 분석 재생성 때 생성합니다.

DB 버전·기업·기간·규칙 파일 해시로 캐시를 구분합니다. 저장된 AI 보고서를 조회할 때도 새 키워드로 전환하지만 Gemini는 자동 호출하지 않습니다. 산업·기업 인사이트는 그대로 유지합니다. 캐시는 앱 저장소에만 쓰며 원격 MySQL은 변경하지 않습니다.

로컬: `.venv\Scripts\python.exe -m snapdart.analyze --llm --sector 반도체`

배포: 이미지를 다시 빌드한 뒤 `docker compose run --rm app python -m cloudapp.cli build --sector 반도체 --llm`, `docker compose up -d`로 실행합니다. Kiwi 0.24.0과 모델 패키지가 이미지 설치 목록에 포함됩니다. Kiwi는 한국어 명사·인접 복합어 추출에 사용합니다. 공식 문서: https://github.com/bab2min/kiwipiepy

추가 섹터의 어휘는 `signal_keyword_rules.py`의 SectorVocabulary에 등록합니다. 미등록 섹터는 공통 규칙만 사용하며 반도체 전용 별칭을 물려받지 않습니다.

패키지 형태의 진단 실행: `python -m dart_remote.dart_signal_wordcloud KRX_SEMI`

분리 테스트: `python -m unittest dart_remote.test_signal_sector_isolation`


## 문장별 근거 선택과 XML 원문 보기 — 2026-10-07

검색과 재무 계산은 기존 MySQL/BGE-M3 경로를 유지합니다. 산업·기업 인사이트와 키워드 설명을 생성할 때는 한 줄 발췌 대신 검색한 청크의 전체 내용을 순서가 있는 문장 ID로 제공합니다. 기업별로 번갈아 후보를 넣으며 최신 사업보고서, 과거 비교 자료, 최신 분기·반기 자료를 포함합니다. 요청당 청크 본문은 기본 48,000자 이내(`CITATION_INPUT_CHAR_BUDGET`)로 제한하고, Gemini의 실제 입력 토큰 계산·TPM/RPM 대기·재시도도 유지합니다. 이 값은 청크를 잘라 인용하는 제한이 아니라 입력 후보 수를 조절하는 제한입니다.

LLM은 요약 문장마다 관련 후보에 직접 뒷받침 F 50%, 이해에 도움 U 20%, 맥락 명확성 C 20%, 시점 부합 T 10%를 0-4 등급으로 부여합니다. 서버가 100점 환산과 불필요한 내용·중복 감점(각 0/5/10점)을 계산합니다. F와 C가 각각 3 이상이고 최종 75점 이상인 적격 청크를 문장마다 최소 2개 선택해야 합니다. 2개 이상 중 충분하면서 불필요한 중복이 적은 개수는 LLM이 결정합니다. 기업 수나 재무 각주 개수는 강제하지 않습니다. 근거가 부족하면 요약을 단정하지 않고 생성하지 않은 이유를 남깁니다.

문장 ID가 이번 입력에 존재하는지, 서로 다른 청크인지, 점수 조건을 통과하는지, 원문 위치가 맞는지와 기존 금액 검증을 수행합니다. 입력 청크와 평가 결과는 LLM 캐시에 보존합니다. 의미적 부합 여부의 등급은 LLM의 판단이며 자동 검증이 사실 정확성을 보증하지는 않습니다. 점수와 선정 이유는 화면에 표시하지 않습니다.

로컬·배포 각주는 모두 MySQL의 `chunk_source_documents`에서 해당 `chunk_id`에 연결된 `document_id`를 찾고, `filing_source_documents.raw_xml`을 읽습니다. 접수번호만으로 본문/첨부 파일을 임의 선택하지 않습니다. 원본·청크·연결 데이터 버전, 접수번호, 원본 byte_size와 SHA-256을 확인한 뒤 안전한 HTML로 렌더링합니다. 근거가 속한 소제목 범위 내 최대 2,000자를 표시하며 걸친 표는 전체 표시합니다. `data/xml_origin` 및 다운로드 명령은 별도 보관용이며 현재 각주 조회에는 사용하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m snapdart.originals --sector 반도체
.\.venv\Scripts\python.exe -X utf8 -m snapdart.analyze --llm --sector 반도체
.\.venv\Scripts\python.exe -X utf8 -m snapdart.market --prices-only
.\.venv\Scripts\python.exe -X utf8 app.py
```

새 프롬프트와 입력은 캐시 키가 달라 기존 구버전 결과를 재사용하지 않습니다. 같은 새 입력으로 재시작하면 완료된 생성 캐시를 이어서 사용하므로 API 오류 후에는 `--llm`으로 다시 실행합니다. `--refresh-llm`은 완료된 새 캐시까지 재생성합니다. 보고서는 전체 생성 성공 후 교체합니다. 원본 XML 재다운로드는 이미 받은 파일을 건너뜁니다.


각주 자연어 기준(2026-10-07): AI 산업 인사이트와 키워드 설명의 근거는 공백을 제외하지 않은 원문 기준 20자 이상인 자연어 문장으로 제한한다. 수치 나열, 표 형식, 독립 숫자가 포함된 정량 문장은 인용 후보에서 제외한다. HBM3 같은 제품명은 허용한다. 재무 데이터는 분석 입력과 그래프에 유지하되 설명 각주의 재무 ID는 허용하지 않는다. 서로 다른 공시 청크 최소 2개 및 기존 점수 기준은 유지한다. 기준 변경으로 분석 재생성이 필요하다.
원본 XML에서 동일 문장이 복수 위치에 존재하고 목차 정보로도 하나로 좁히지 못하면, 실제 후보 위치별 주변 500자와 소제목, 요약 문장을 Gemini에 전달하여 기존 F/U/C/T·감점 기준으로 평가한다. 코드는 적격 후보 중 최고점을 선택하고 동점은 원문 순서를 따른다. 결과는 프로세스 내 캐시를 사용한다. 최초 중복 위치 조회에는 Gemini 호출과 대기가 발생할 수 있다. 일치 위치가 전혀 없거나 평가 실패 시 원문 위치를 만들어내지 않는다. 선택한 소제목 내 최대 2,000자 및 표 전체 표시 규칙은 유지한다.


섹터 표시 범위: 기본값은 MySQL에 등록된 운영 가능한 섹터 전체입니다. 섹터별 분석 자료 오류는 해당 섹터의 준비 중 상태로 표시하며 다른 섹터의 화면을 중단하지 않습니다. 로컬에서 반도체만 실행하려면 `python -X utf8 app.py --sector 반도체`를 사용합니다. 배포에서는 `SNAPDART_SECTORS=반도체`로 제한할 수 있고, 비워두면 전체 섹터를 표시합니다.

원본 XML 파싱은 먼저 최소 복구 후 엄격한 파싱을 시도합니다. 태그 형태로 적힌 캡션·제품명은 원문 그대로 텍스트화하고, 여전히 태그 불일치가 있으면 외부 엔티티·네트워크·DTD 접근을 차단한 lxml 복구를 시도합니다. 복구 후 독립적으로 읽은 원문 텍스트와 일치해야 표시하며, 불일치하면 원문 표시를 중단합니다. MySQL의 XML BLOB은 수정하지 않습니다. 설치 의존성에 lxml이 추가되었습니다.


기본 전체 섹터 실행(2026-10-07): 로컬 `python -X utf8 -m snapdart.analyze --llm`은 현재 MySQL의 전체 운영 섹터·기업을 순서대로 분석합니다. `--sector 반도체`를 명시하면 반도체만 처리합니다. 한 섹터 실패 시 나머지 섹터 처리를 계속한 뒤 실패 목록을 보고합니다. 배포 CLI `python -m cloudapp.cli build --llm`도 같은 기본 범위를 사용합니다.
로컬 `python -X utf8 app.py`는 전체 섹터를 표시하며 시세 수집은 백그라운드로 실행합니다. 전체 기업 주가부터 수집한 뒤 섹터별 공식 KRX 지수를 갱신합니다. 첫 화면은 저장된 보고서·시세와 MySQL 섹터 목록만 읽으며 보고서 생성과 BGE-M3 검색을 실행하지 않습니다. 보고서 생성은 분석 명령이나 해당 산업 화면의 기존 보고서 로딩 경로에서 수행합니다. `app.py --sector 반도체`로 명시한 경우에만 로컬 화면·시세를 제한합니다.

최신 각주 기준(2026-10-07): 이전의 공시 청크 최소 2개 조건을 폐기했습니다. 산업·기업 인사이트와 키워드 설명 모두 문장마다 적격 자연어 근거 1개 이상이면 생성합니다. 근거가 하나뿐이면 확인 가능한 범위의 산업 인사이트 한 문장도 허용합니다. 근거가 없는 문장은 생성하지 않습니다. 자연어 20자 이상, F/C 등급 및 최종 점수 기준, 원문 ID 검증은 유지합니다. 한 기업의 신호를 산업 전체 현상으로 일반화하지 않는 원칙도 유지합니다. 프롬프트와 캐시 키가 변경되어 다음 분석 실행 시 새 기준으로 생성합니다.

## 산업별 KRX 지수 시세

반도체·헬스케어·철강 화면은 각각 `KRX 반도체`, `KRX 헬스케어`, `KRX 철강`의 공식 종가를 표시합니다. API 지수명은 MySQL `krx_indices.index_name`을 사용합니다. 공식 코드가 없는 산업은 내부 구성종목 코드로 저장 자료를 식별하며, 공식 지수 코드를 임의로 만들지 않습니다.

`.env`의 승인된 `KRX_API`를 사용합니다. 다음 명령은 등록되어 있고 분석 데이터가 있는 모든 산업의 지수를 갱신합니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m snapdart.market --index-only
```

기존과 같이 최근 3년을 수집하며 실행일 당일 시세는 제외합니다. 전일까지의 마지막 거래일 종가와 직전 거래일 종가를 비교합니다. 날짜별 원응답은 `data/krx_api/daily_responses/`, 산업별 이력은 `data/krx_api/*_days.json`에 저장합니다(반도체는 기존 `index_days.json`). 한 날짜의 원응답을 산업 간 공유하여 중복 API 호출을 줄입니다. 화면용 자료는 `data/service/market/` 및 기존 반도체 `data/service/market.json`, 산업별 서비스 캐시에 반영합니다. 수집 실패 시 동일 지수의 저장 자료만 유지합니다. 프로그램 시작 시에도 기존 시세 갱신 절차가 적용됩니다.


### 첫 화면 규모 표시와 프롬프트 정의서 대조 (2026-10-07)

첫 화면 원의 면적은 전체 KRX 지수 구성종목 시가총액 합계에 비례합니다. `KRX 시리즈 일별시세정보` API 응답의 `MKTCAP`을 사용하며 대표 분석기업 합계로 대체하지 않습니다. 지름은 최대 원 지름 × √(해당 지수 시가총액 / 최대 지수 시가총액)입니다. 실행일 당일을 제외한 마지막 거래일의 시가총액과 지수 종가를 함께 저장합니다. 휴장일에는 직전 거래일을 사용하며 기준일은 마우스를 올리면 확인할 수 있습니다. 작은 원의 산업명은 원 아래에 표시합니다. API 오류 시 기존 값을 보존하고, 자동 갱신 경로는 갱신 실패 여부를 표시합니다.

산업 인사이트는 기업별 수치가 같은 방향으로 움직이는지뿐 아니라, 서로 다른 변화가 공시로 확인되는 공통 산업 요인에 연결되는지도 분석합니다. 공통 요인이 확인되면 기업별 주력 사업과 대응 차이를 설명하고, 연결 근거가 없으면 주요 변화를 구분합니다. 키워드 설명 입력에는 실제로 계산된 언급 청크 수·언급 비율·변화 지표도 함께 전달합니다. 점수나 키워드 선정 이유는 고객에게 표시하지 않습니다.

Temperature는 정의서 및 Gemini 3 권장 기본값에 맞춰 1.0을 사용합니다. 정의서의 초기 출력 한도 500/300토큰과 단일 문자열 JSON은 이후 요청한 문장별 근거 평가·원문 ID·각주 출력을 담을 수 없어 적용하지 않습니다. 기존 8,192토큰 한도와 구조화된 근거 평가 JSON을 유지하며, 고객용 산업 요약은 1-3문장, 키워드 설명은 1-2문장입니다. 기업 언급 개수 제한을 두지 않고 적격 근거 하나로도 생성할 수 있습니다. 근거 문장 선정 프롬프트와 점수·자연어 검증은 변경하지 않았습니다.

새 프롬프트는 다음 `--llm` 분석부터 적용되며 입력·지시문별 캐시가 구분됩니다. 화면 새로고침만으로 기존 저장된 인사이트를 재생성하지 않습니다.

### 인사이트 생성 속도 개선

인사이트 생성은 기본 4개 작업을 동시에 처리합니다. `GEMINI_CONCURRENCY=1`이면 기존 순차 처리, 2-4이면 제한된 병렬 처리입니다. 기본 RPM 10·TPM 225,000 예산은 유지하며 로컬에서는 잠금으로 예약을 보호하고 배포에서는 기존 SQLite/GCS 공유 예약을 사용합니다. 대기 중에는 예약 잠금을 잡지 않습니다. 각 재시도·교정 요청도 사용량을 예약합니다.

한 번의 보고서 생성에서 동일 재무 조회·검색 결과를 재사용하고, 정확히 같은 요청의 API 토큰 계산 결과도 프로세스 내에서 최대 256개 재사용합니다. 입력을 줄이거나 근거 점수·문장 검증을 생략하지 않습니다. 산업·기업·키워드 설명 개수와 근거 선정 프롬프트는 유지합니다. 작업별 출처를 분리해 동일 원문이라도 요약 문장별 평가가 덮어써지지 않도록 합니다. 모든 작업과 최종 데이터 버전 검증이 성공해야 보고서를 교체하며, 실패 시 완료된 생성 캐시와 기존 보고서를 보존합니다.

실행 방법은 기존과 같습니다. `--llm`은 완료된 동일 입력 캐시를 재사용하고 `--refresh-llm`은 모두 재생성합니다. 새 분석에서 진행 건수를 표시합니다. 한도 대기가 주된 병목이면 병렬 처리의 속도 개선은 제한적입니다.

## MySQL 최신 스냅샷 확인 (2026-10-08)

현재 검증된 버전은 `2026-10-08-dart25-bank-xml-v1`, 임베딩 버전은 `bge-m3-2026-10-08-dart25-bank-xml-v1`입니다. 자동차·은행/금융지주·헬스케어·반도체·철강 5개 섹터, 25개 기업의 2023-2025년을 조회했습니다. 청크와 임베딩은 각각 147,720개, 원본 XML은 399개입니다. 청크·벡터 계약 검증, XML 전체 크기 및 SHA-256 검증, 청크→XML 고아 연결 검사를 통과했습니다. 추가된 금융업 지표 테이블은 기존 테이블을 대체하지 않는 확장 테이블이며, 현재 화면은 기존 표준화 재무 조회를 유지합니다. 금융업 전용 지표 화면은 이번 변경에 포함하지 않았습니다.

버전은 코드에 고정하지 않습니다. 매 실행 시 `data_versions`의 검증된 현재 버전 및 `embedding_metadata`를 조회합니다. 보고서 `source`에는 `data_version`과 `index_version`을 함께 기록하며, 이전 보고서는 기존 지문 비교에 따라 재생성이 필요합니다. 연도 조회 결과가 비어 있으면 다른 버전으로 우회하지 않고 현재 버전과 coverage 버전을 오류 메시지로 안내합니다.

검사 결과 JSON은 로컬 `data/service/database_snapshot.json`, 배포 `config/database_snapshot.json`에 저장했습니다. 이는 검사 시점의 기록이며 실행 버전을 결정하는 설정 파일이 아닙니다. 원격 MySQL의 테이블·메타데이터에는 쓰기 작업을 수행하지 않았습니다.

## 전체 적재 기간 분석 (2026-10-08)

`--years`를 생략하면 현재 MySQL 데이터 버전의 해당 섹터에 존재하는 모든 연도를 분석하고 표시합니다. 기업별 재무 추이, 공시 조회와 근거 검색, 산업/기업 인사이트 입력 및 그래프가 같은 전체 기간을 사용합니다. `--years`를 지정하면 지정 연도로 한정합니다. 기존 보고서는 기간 정책 변경으로 재생성이 필요합니다. 현재 DB의 기간은 2023-2025년이므로 지금은 화면의 연도 수가 같지만, 과거 또는 신규 연도 적재 시 자동으로 포함됩니다.

공시 신호 워드클라우드의 변화 점수도 전체 연도를 사용합니다. 인접 연도 언급 비율 차이에 최근 구간일수록 큰 비중을 주어 가중평균합니다. 구간 가중치는 0.4에서 0.6까지 선형으로 배분하고 합이 1이 되도록 정규화합니다. 3개년일 때 기존 0.4/0.6 계산과 같고, 2개년이면 두 연도의 차이, 1개년이면 변화는 0입니다. 최신 연도 언급 수준·기업 간 확산 및 다른 점수 기준은 유지하며, 전체 기간을 반영한 결과를 최신 연도 워드클라우드에 표시합니다. 시세 수집 기간과 전일 종가 기준은 별도 정책으로 유지합니다.

## 재무 JSON 부재 시 XML 보완 (2026-10-08)

`dart_remote/xml_financials.py`는 해당 기업·연도·보고서의 JSON에서 적재한 재무 자료가 없을 때에만 작동합니다. MySQL에는 JSON 파일 자체가 아닌 적재된 행이 있으므로, `financial_facts`의 활성 행과 `coverage.financial_exists`로 존재 여부를 확인합니다. 다른 연결/별도 기준에 재무 자료가 있거나, JSON의 계정이 표준화되지 않아 화면 지표만 없는 경우에도 XML 보완을 실행하지 않습니다. 기존 수치가 일부만 누락되었다는 이유로 XML을 섞지 않습니다.

자료가 없으면 해당 기간의 최신 활성 공시 접수번호에 속한 원본 XML들을 조회하여 크기·SHA-256을 검증합니다. 기존 안전 XML 파서를 이용해 연결/별도 재무제표의 표를 복원하고, 명시된 계정·기간·단위·열 제목이 일치하는 수치만 원 단위로 변환합니다. 매출액, 영업이익, 재고자산, 영업활동현금흐름과 직접 공시된 유형자산 취득액을 지원합니다. 분기와 누적값을 구분하며, 명시되지 않은 값은 LLM으로 추정하지 않습니다. 서로 다른 표의 값이 충돌하거나 원문 보존·기간·단위를 확정하지 못하면 결측으로 유지합니다. 유형자산과 무형자산의 합계를 CAPEX로 대체하지 않습니다.

추출 행에는 문서 ID·접수번호·재무 기준·기간 유형·표/행/열 위치와 원본 표 구조를 저장합니다. 그래프의 출처 버튼은 XML 보완값에 대해 복원된 원본 표를 표시하고 추출한 셀을 강조합니다. 기존 JSON 값의 출처 처리와 자연어 인사이트 각주 기준은 유지합니다. 추출값과 검증 안내는 서비스 캐시에 저장하며, 원본 XML 해시·데이터 버전·파서 버전이 바뀌면 새로 처리합니다. 원격 DB에는 쓰지 않습니다. 이 기능은 로컬/배포의 공통 재무 조회 경로에서 작동하므로 재무 추이·분기 계산·LLM 입력이 같은 값을 사용합니다. 보고서 정책 지문을 변경했으므로 기존 분석은 재생성해야 합니다.

실데이터 확인: 삼성전자 2024년 연결 XML의 5개 지원 지표가 기존 JSON 적재값과 일치했습니다(실제 조회는 JSON 유지). 재무 JSON이 없는 카카오뱅크 2023년 Q1 별도 XML에서 매출/영업수익, 영업이익, 영업활동현금흐름을 반환했습니다. 일부 금융사 원문은 안전 파싱 또는 기간·표 구조 확인 조건을 통과하지 못하므로 여전히 결측일 수 있습니다. 이는 모든 공시 형식의 추출을 보장하는 기능이 아닙니다.


시세 자동 갱신(2026-10-08): 로컬과 배포 서버 모두 기본 시작 시 백그라운드에서 분석 대상 기업 주가와 MySQL 등록 산업별 KRX 지수·전체 시가총액을 갱신합니다. 산업 지수명은 krx_indices.index_name에서 읽습니다. 주가·지수는 실행일 이전 마지막 거래일 종가 기준이며, 개별 기업 시가총액은 네이버 조회 시점 값입니다. 실패 시 기존 자료를 유지합니다. 매일 반복 실행하는 예약 기능은 아닙니다. 배포에서 자동 갱신을 생략하려면 `python -m cloudapp.serve --no-market-refresh` 또는 `NO_MARKET_REFRESH=1`을 사용합니다. Docker Compose에서는 `docker compose run --rm --service-ports app python -m cloudapp.serve --no-market-refresh`로 별도 실행할 수 있습니다. 기존 app이 실행 중이면 포트 충돌을 피하도록 먼저 중지해야 합니다.


## 분석 프롬프트 버전 (2026-10-08)

기본 `--prompt-version new`는 docs/4차구상/프롬프트_정의서_수정.txt 원문을 반영합니다. 기업 인사이트도 1-3문장이며 근거 점수는 F 40%, U 30%, C 20%, T 10%입니다. `--prompt-version old`는 prompts_old.py와 citation_selection_old.py의 기존 문구·기업 문장 수 제한·F 50%, U 20% 평가를 사용합니다. 입력 자료와 사실·수치 검증은 유지하며, 버전별 생성 캐시는 분리됩니다. 화면에는 마지막으로 성공하여 저장된 보고서가 표시됩니다. 버전 선택만으로 과거 보고서가 자동 표시되는 것은 아닙니다. 원문 중복 위치의 표시 평가에는 현재 기본 평가 기준을 사용합니다.

로컬: `python -X utf8 -m snapdart.analyze --llm --prompt-version new` 또는 `--prompt-version old`. 배포: `docker compose run --rm app python -m cloudapp.cli build --llm --prompt-version new` 또는 `--prompt-version old`. 특정 산업만 처리하려면 `--sector 반도체`를 추가합니다. 동일 버전의 완료 생성 캐시는 재사용하며 강제 재생성에는 `--refresh-llm`을 사용합니다.
