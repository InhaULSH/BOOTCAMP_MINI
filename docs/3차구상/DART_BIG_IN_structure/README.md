# DART BIG:IN — 데이터 연결용 UI 구조

이 패키지는 2026-10-06 최신 화면 구조를 바탕으로 정리한 독립 프런트엔드입니다.
기존 시안의 가상 시가총액·주가·재무·공시 문구·LLM 결과는 포함하지 않습니다.
현재 공개된 시안에는 예시 데이터가 남아 있으며, 이 패키지는 해당 시안의 코드를 데이터 연결용으로 별도 정리한 버전입니다.

## 실행

압축을 푼 폴더에서 실행합니다.

```sh
python serve.py
```

브라우저에서 http://localhost:8000 을 여세요. macOS/Linux는 python3를 사용할 수 있습니다.
별도 npm 설치나 빌드는 없습니다. HTML 파일 더블 클릭 대신 HTTP 서버로 실행하세요.

## 데이터 연결

1. `data/project.json`에 실제 데이터를 넣으면 화면에 표시됩니다. 기본값은 빈 배열입니다.
2. 실제 API를 사용하려면 `assets/data.js`의 `loadProject()`만 변경하세요.
3. 데이터 필드와 단위는 `DATA_CONTRACT.md`에 정의되어 있습니다.
4. 데이터가 없거나 분모가 0이면 숫자를 만들어내지 않고 빈 상태 또는 `—`를 표시합니다.

## 화면

- `index.html`: 고정 배치 섹터 원. 마우스/키보드 초점으로 제자리 정보 카드 표시.
- `industry.html?sector=<id>`: 섹터지수, 산업 공시 클라우드, AI 산업 인사이트, 기업 카드, 4개 재무 그래프, 기업 비교표.
- `company.html?company=<id>`: 기업명 주가 그래프, 기업 공시 클라우드, AI 기업 인사이트, 해당 기업의 지표. 기업 간 비교표 없음.

기업 카드를 누르면 해당 기업 상세 화면으로 이동합니다.
재무 그래프는 모든 분기를 위에 `23`, 아래에 `Q1` 형태로 표시합니다.
기업별 선의 범례에 마우스를 올리거나 키보드 초점을 주면 그 기업 선이 강조됩니다.

## 시가총액과 원의 크기

`cap = 전체 KRX 섹터지수 구성종목 시가총액 합계`

`diameter = viewportBound × sqrt(cap / maxCap)`

따라서 **원의 면적 비율 = 시가총액 비율**입니다.
반도체나 특정 기업의 시가총액, 고정 원 크기를 데이터로 하드코딩하지 않습니다.
`viewportBound`와 원의 배치 좌표는 화면에 맞추는 디자인 규칙입니다.
대상 5개 기업만 합산하지 않고 전체 지수 구성종목을 합산해야 합니다.
구성종목 목록이 있으면 전체 목록에서 계산하고, 없으면 서버에서 산출한 전체 합계를 사용합니다.

원의 색은 입력된 KRX 섹터지수 수익률입니다. 빨강은 상승, 파랑은 하락입니다.
색 농도는 전달된 섹터 수익률의 최대 절댓값에 맞춰 상대적으로 조정합니다.
비교하는 5개 기업의 평균 수익률로 대체하지 않습니다.

## 계산과 역할 분리

- `assets/data.js`: API 어댑터, 전체 시가총액 합계, 매출 정규화, 재무 비율 계산.
- `assets/charts.js`: 선 그래프, 중요도 기반 워드클라우드, 툴팁.
- `assets/app.js`: 페이지 구조, 데이터 바인딩, 이동, 설명 팝업, 범례 강조.
- `assets/home.css`, `assets/analysis.css`: 화면 디자인.
- `assets/fonts`: 나눔고딕.

매출 지수는 기업별 첫 표시 분기를 100으로 계산합니다.
조회기간의 첫 분기가 2023 Q1이면 모든 기업의 2023 Q1이 100입니다.
기준 분기 매출이 없거나 0이면 그 기업의 매출 지수를 계산하지 않습니다.
기준 분기를 기업마다 다른 분기로 자동 대체하지 않습니다.
영업이익률 = 영업이익 / 매출액 × 100.
CAPEX 비율 = CAPEX / 매출액 × 100.
FCF 비율 = (영업활동현금흐름 - CAPEX) / 매출액 × 100.

워드클라우드에는 LLM이 산출한 `importance`를 전달합니다.
등장 횟수로 중요도를 대신 산출하는 로직은 없습니다.
AI 인사이트와 공시 맥락·선정 이유도 서버/LLM 결과를 전달받아 표시합니다.

## 포함하지 않는 기능

실제 DART/KRX 호출, DB, 로그인, LLM 요청 및 프롬프트 구현은 이 프런트엔드의 범위가 아닙니다.
이 패키지에 API 키, 호스팅 프로젝트 ID, 저장소 인증정보는 없습니다.
