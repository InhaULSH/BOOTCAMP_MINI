# 인사이트 생성과 프롬프트

확인 기준일: 2026-10-08. [문서 목록](README.md)

## 구현 의도

초보 사용자가 공시에서 확인되는 사업 현황과 변화 방향을 짧게 이해하도록 한다. 자료를 많이 나열하거나 “다양한 동향”, “기업별 기준 차이”로 설명을 끝내는 것을 억제하되, 근거가 확인되지 않은 공통 원인이나 미래 전망을 만들지 않도록 구성했다.

## Gemini에 실제로 입력하는 자료

사업보고서 전체 XML이나 전체 저장 벡터를 한 요청에 넣지 않는다. 산업 인사이트는 기업별 검색 주제를 통해 모은 공시 후보를 사용한다. 최신 분석 연도는 보고서 기간별 최대 2개, 과거 연도는 기간별 최대 1개를 우선 후보로 넘긴다. 사업·분기·반기보고서가 자료에 있으면 검색 대상에 포함된다.

최종 입력은 자연어 근거 문장이 있는 청크를 기업별로 번갈아 고르고, 최신 사업보고서 등을 우선해 문자 예산 안에 구성한다. 기본 `CITATION_INPUT_CHAR_BUDGET`은 48,000자이며, 청크 중간을 임의로 자르는 대신 예산에 들어오는 전체 청크를 사용한다. 이는 공시 본문 후보의 예산으로 프롬프트·재무정보·JSON 형식을 포함한 최종 토큰 수와는 다르다.

각 청크에는 `t1` 같은 요청 내 ID와 기업·연도·기간·섹션·본문, 인용 가능한 문장 및 문자 위치가 붙는다. 재무정보는 연간 이력과 최신 연도의 Q1·H1·Q3 누적값 등을 별도 수치 자료로 제공한다. `f1` 같은 재무 ID는 분석 입력용이다. 같은 청크를 context에 중복해서 넣지 않는다.

워드클라우드의 단어 설명은 선택 단어로 최신 분석 연도의 사업 관련 공시를 검색한다. 계산된 언급 청크 수·기업 수·언급 비율·변화값 등이 있으면 정의와 함께 전달한다. 언급 증가를 실제 수요·매출 증가로 바꾸어 해석하지 않도록 지시한다. 이 생성 경로에 웹 검색 도구나 뉴스 검색 API를 연결하지 않는다.

## new와 old 프롬프트

현재 기본 `new`는 [프롬프트_정의서_수정.txt](프롬프트_정의서_수정.txt)를 반영한다. 공통 원칙, 산업·기업·키워드별 지시, 문장별 공시 근거 선택 지시를 연결해 사용한다. 산업과 기업 인사이트는 1-3문장, 키워드 설명은 1-2문장이다. 충분한 근거가 없으면 빈 `sentences`와 `insufficient_reason`을 허용한다.

| 항목 | new | old |
| --- | --- | --- |
| 분석 원칙 | 사용자 수정 정의서 | 수정 직전 상수 보존 |
| 기업 인사이트 문장 수 | 1-3문장 | 코드의 별도 최대 제한 없음 |
| F·U·C·T 가중치 | 40%·30%·20%·10% | 50%·20%·20%·10% |
| 적격 공시 청크 최소 수 | 문장마다 1개 | 문장마다 1개 |
| 캐시 | 프롬프트 버전과 실제 지시를 포함해 분리 | 별도 키로 분리 |

`--prompt-version new|old` 또는 Python 호출에서 `LLM_PROMPT_VERSION`으로 선택한다. CLI의 기본 옵션은 `new`이므로 CLI에서는 옵션으로 선택하는 편이 명확하다. 버전을 선택하는 것만으로 과거 보고서가 화면에 나타나지는 않는다. 해당 버전으로 생성이 성공해 저장된 최신 보고서가 표시된다.

new 코드는 [prompts.py](../../snapdart/data_access/prompts.py)와 [citation_selection.py](../../dart_remote/citation_selection.py), old 코드는 [prompts_old.py](../../snapdart/data_access/prompts_old.py)와 [citation_selection_old.py](../../dart_remote/citation_selection_old.py)에 있다. 배포에도 대응 파일이 있다.

## Gemini의 평가와 코드의 검사

정상 생성 호출에서 Gemini는 설명문과 선택 청크의 평가를 함께 반환한다. 별도 독립 심사 모델이 설명문을 먼저 검증하는 방식은 아니다. 모델이 반환하는 등급은 각각 0-4이고 코드는 다음 공식으로 점수를 계산한다.

`점수 = max(0, 25 × (0.40F + 0.30U + 0.20C + 0.10T) - 관계없는 내용 감점 - 반복 내용 감점)`

| 평가 | 뜻 | 현재 비중 |
| --- | --- | --- |
| F | 요약의 사실을 직접 뒷받침하는가 | 40% |
| U | 초보 사용자가 사업 신호를 이해하는 데 도움이 되는가 | 30% |
| C | 주어·제품·행위·조건이 명확한가 | 20% |
| T | 요약 시점과 실제 사건 시점이 맞는가 | 10% |

두 감점은 각각 0·5·10점 중 하나다. 예를 들어 F=4, U=3, C=4, T=3이고 반복 감점만 5점이면 `25 × 3.6 - 5 = 85점`이다. 최종 적격 조건은 `suitable=true`, F≥3, C≥3, 점수≥75이다. 점수가 높아도 F 또는 C가 낮으면 거절한다. T는 별도 최소 등급을 두지 않는다.

요약 문장마다 적격 자연어 공시 청크를 최소 1개 선택해야 한다. 같은 청크의 여러 문장은 청크 하나로 센다. 코드가 입력 ID, 문장 ID, 실제 문자 위치, 평가 형식·등급·감점·점수·개수를 검사한다. 자연어 근거는 20자 이상이며 표의 셀·수치 나열·금액·비율은 공개 각주로 선택하지 않는다. 독립된 숫자가 있는 문구를 보수적으로 제외하므로 연도가 들어간 유용한 문장도 제외될 수 있다.

재무 자료는 해석에 활용하지만 각주의 `refs`에는 자연어 공시 근거만 사용한다. 요약에 금액이 포함되면 같은 기업의 입력 수치 또는 인용 본문과 일치하는지도 검사하며 반올림 범위를 허용한다. 형식·출처 검증은 모든 문장의 의미 관계를 자동으로 완전히 입증하는 검증과는 다르다.

## 사용량·동시 실행·결과 보존

Gemini 요청은 `countTokens`로 최종 입력을 세고 자체 TPM·RPM 예약 후 실행한다. 기본 코드 예산은 `GEMINI_TPM_BUDGET=225000`, `GEMINI_RPM_BUDGET=10`이며 실제 프로젝트 한도에 맞춰 설정해야 한다. 이 값 자체가 계정의 공식 한도를 확인한 값은 아니다.

`GEMINI_CONCURRENCY`의 미지정 기본은 4이고 1-4로 제한된다. 작업은 독립된 산업·기업·단어 설명 단위로 병렬 실행하지만 사용량 예약은 함께 적용한다. 429·일시적 서버 오류·네트워크 오류에는 제한된 재시도를 수행한다. 403 인증 오류나 단일 입력 예산 초과는 대기로 해결되지 않는다. 구조나 근거 검증 실패도 성공 결과로 저장하지 않는다.

완료된 기능별 LLM 캐시는 재사용할 수 있다. 프롬프트·입력·모델이 바뀌면 키가 달라지고 `--refresh-llm`은 완료 캐시 재사용을 건너뛴다. 한 산업의 생성 작업이 모두 성공하고 DB 버전이 유지되어야 최종 보고서를 저장한다. 실패 시 기존 보고서는 보존하지만, 다른 산업의 성공 결과는 저장될 수 있다. 자체 예약은 다른 프로그램이 사용하는 동일 API 프로젝트의 모든 사용량을 알 수는 없다.

## 적용 범위와 확인 파일

`snapdart.query --llm`의 짧은 질의 응답은 공통 원칙과 입력 ID 검증을 사용하지만, 보고서 인사이트의 F·U·C·T 평가 전체를 동일하게 수행하지는 않는다. 원문에 같은 인용문이 여러 번 등장할 때 위치를 고르는 평가는 현재 기본 기준을 사용하며, old 보고서 생성과 별개다.

- [pipeline.py](../../snapdart/data_access/pipeline.py): 입력 구성·버전 선택·출력·금액 검증·LLM 캐시
- [generation.py](../../dart_remote/generation.py): 동시 생성과 결과 합치기
- [llm.py](../../snapdart/llm.py): 토큰 계산·TPM/RPM·API·응답 검사
- [test_prompt_contract.py](../../tests/test_prompt_contract.py): 정의서와 코드, new/old 계약
- [test_citation_selection.py](../../tests/test_citation_selection.py), [test_generation_concurrency.py](../../tests/test_generation_concurrency.py): 각주 조건과 동시 실행

Gemini의 JSON 구조화 출력은 형식을 지정하는 수단이다. 내용의 정확성은 프로젝트의 별도 검증으로 다룬다. 관련 외부 기술 설명은 [Google 구조화 출력 공식 문서](https://ai.google.dev/gemini-api/docs/structured-output)를 참고할 수 있으며, 위 동작 설명의 직접 근거는 현재 코드다.
