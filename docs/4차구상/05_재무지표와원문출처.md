# 재무 지표와 원문 출처

확인 기준일: 2026-10-08. [문서 목록](README.md)

## 구현 의도

금액을 문구 검색이나 Gemini의 기억에서 추정하지 않고 재무 DB에서 읽는다. 기업·기간·연결/별도·단위·누적/단일 기간을 구분해 계산하고, 계산에 사용한 원래 수치와 표를 확인할 수 있도록 출처를 남긴다.

## 재무 수치의 우선순위

서비스는 MySQL `standardized_financials`를 우선 조회한다. 계정명과 계정 ID를 확인해 매출, 영업이익, CAPEX, 영업활동현금흐름, 재고 등을 읽는다. 같은 기준에 다른 값이 동시에 있으면 임의로 하나를 선택하지 않고 오류를 낸다. 원 단위·KRW와 손익계산서·현금흐름표 등 지표별 재무표를 구분한다.

표준화 뷰에서 누락된 영업이익(손실) 일부 행은 `financial_facts`의 정확한 영업이익 계정 ID·별칭으로 보완한다. 매출총이익이나 계속영업이익을 영업이익으로 바꾸는 추정은 하지 않는다.

연간 이력은 연결(CFS)을 우선하고 해당 기준의 재무 행이 없으면 별도(OFS)를 조회한다. 서로 다른 기준의 연간 값으로 전년 대비 변화율을 계산하지 않는다. 전년 값이 0 이하인 변화율은 현재 계산 규칙상 표시하지 않을 수 있다. 화면의 최신 분기 지표와 이 연간 변화율은 구분해야 한다.

## JSON 재무 자료가 없는 보고서의 XML 보완

현재 저장소는 원래 JSON 파일의 로컬 존재 여부를 확인하는 구조가 아니다. 해당 기업·연도·보고서의 활성 `financial_facts` 행 또는 `coverage.financial_exists=1`이면 JSON 기반 재무 자료가 존재한다고 판단한다. 연결·별도 중 한쪽에 자료가 있는 경우도 보고서 단위 존재 판정에 포함된다.

요청한 재무 행이 없고 위 보고서 단위 JSON 자료도 없을 때만 `xml_financials.py`가 원본 XML의 재무표에서 수치를 보완한다. JSON에 한 지표만 빠졌거나 다른 재무 기준의 자료가 있다는 이유로 XML 보완을 실행하지 않는다. 이는 기존 JSON 수치와 XML 해석을 무분별하게 섞지 않기 위한 조건이다.

XML 보완은 연결/별도 재무표, 계정명, 단위, 열의 연도·기말 또는 기간을 확인한다. 금액을 원 단위로 바꾸고 표·행·열 위치, 문서·접수번호 등을 붙인다. 기간·단위가 불명확하거나 같은 지표 값이 충돌하면 추정하지 않고 비워 둔다. 인식 규칙이 모든 회사의 모든 재무표 형식을 처리한다는 보장은 없다. 추출 결과는 앱 캐시에 저장하고 원천 MySQL은 수정하지 않는다.

## 분기 수치와 그래프

Q1·H1·Q3·FY를 각각 Q1-Q4 화면으로 연결한다. 직접 분기값이 있으면 우선 사용하고, 없으면 같은 연결/별도 기준의 누적값을 차감한다.

- Q1: 1분기 수치
- Q2: 반기 누적 - 1분기 누적
- Q3: 3분기 누적 - 반기 누적
- Q4: 연간 - 3분기 누적

필요한 이전 누적값이 없으면 분기값은 비어 있다. 이를 0으로 대체하지 않는다. 직접 분기값이 계산된 값인지 여부도 출처 구성에서 구분하며, 누적 차감으로 만든 분기의 출처는 차감에 사용한 보고서들을 함께 표시한다. CAPEX가 음수로 계산된 경우 현재 화면용 변환은 값을 비운다.

| 현재 그래프 | 산식 |
| --- | --- |
| 매출 성장 추이 | 해당 분기 매출 ÷ 첫 표시 분기 매출 × 100 |
| 영업이익률 | 분기 영업이익 ÷ 분기 매출 × 100 |
| 매출 대비 CAPEX | 분기 CAPEX ÷ 분기 매출 × 100 |
| 투자 후 남은 현금(FCF) | (분기 영업활동현금흐름 - 분기 CAPEX) ÷ 분기 매출 × 100 |

따라서 현재 그래프를 일괄적인 전년 대비 변동률 그래프라고 설명하면 안 된다. 산업 화면의 상단 수치는 최신 분기에서 값이 있는 기업들의 중앙값이다. 지수 비중 가중평균·지표 단순합을 표시하는 초기 화면과 다르다. 첫 표시 분기의 매출이 없거나 0 이하이면 해당 기업의 매출 지수도 계산하지 못한다.

## 수치의 원본 표와 설명문의 각주

수치 출처는 `/api/revenue-source` 또는 `/api/quarter-source`로 조회한다. DB 재무 행의 기업·접수번호·연도·재무 기준·계정과 연결된 원본에서 표를 찾는다. XML 보완값은 저장한 표·행·열 정보를 사용한다. 표의 병합 셀과 전체 행·열을 유지해 원래 표를 보여주고 사용한 셀을 강조한다. 정확한 위치를 확인하지 못하면 임의의 다른 표를 정확한 출처라고 표시하지 않는다.

인사이트의 각주는 `/api/source`로 조회한다. 등록된 청크 ID와 인용문·문자 위치를 확인하고 `chunk_source_documents`로 연결된 `filing_source_documents.raw_xml`을 읽는다. 원본의 버전·크기·해시를 검사한다. 본문 인용은 주변 내용을 보여주고, 같은 인용문이 여러 위치에 남으면 제목·섹션으로 좁히거나 Gemini의 위치별 평가를 사용한다.

XML은 인코딩 확인, 제한된 문자 정리, 엄격 파싱과 복구 파싱을 순서대로 사용한다. 원본 바이트는 보존하며 화면에 XML 태그를 그대로 노출하지 않는다. 외부 엔티티·네트워크 해석을 제한하고 표시 HTML은 안전한 태그로 구성한다. 복구 파싱을 통과했다고 모든 문서의 완전한 복원을 보장하는 것은 아니다. 원문 검증과 출처 위치 확인에 실패하면 그 상태를 오류로 다룬다.
