# 09. 디자인 언어와 UI 구현

확인 기준: 2026-10-11의 로컬 코드와 `deploy/` 공통 화면 코드. 이 문서는 구현된 현재 동작을 설명합니다. 과거에 제안했지만 현재 코드에는 없는 동작은 구현 사실로 다루지 않습니다.

## 1. 이 화면은 사용자가 무엇을 이해하도록 돕는가

DART BIG:IN은 산업의 시장 움직임, 공시에서 읽은 사업 변화, 기업의 재무 흐름을 이어서 살펴보는 서비스입니다. 화면의 목적은 많은 숫자를 한꺼번에 보여주는 것보다 사용자가 관심 산업을 고르고, 변화의 의미를 읽고, 궁금한 기업과 근거로 들어가도록 돕는 데 있습니다.

처음에는 산업을 고릅니다. 산업 화면에서는 지수와 공시 키워드로 현재 관심사를 파악하고, AI 인사이트로 사업 변화를 읽은 뒤, 기업 카드와 재무 그래프로 상세 내용을 확인합니다. 기업 화면에서는 같은 화면 구성을 해당 기업의 자료로 좁힙니다. 설명이 궁금하면 물음표를, 근거가 궁금하면 각주나 재무 그래프의 관측점을 선택합니다.

이 흐름을 유지하기 위해 넓은 여백, 흰 카드, 차분한 회색 본문, 파란색 조작 요소를 사용합니다. 의미를 구별해야 하는 시장 등락과 기업·단어 구분에는 별도의 색을 씁니다. 디자인을 바꿔도 DB 검색 범위, 공시 근거 선정, 지표 계산식은 디자인 코드에서 변경하지 않습니다.

## 2. 토스 디자인 언어를 어떻게 참고했는가

[TDS 공개 색상 문서](https://tossmini-docs.toss.im/tds-react-native/foundation/colors/)는 색을 공통 이름으로 관리해 일관된 화면을 만드는 방식을 설명합니다. 이 앱은 그 방식을 참고하여 배경·본문·보조 설명·테두리·조작 요소의 역할을 CSS 변수로 나눴습니다. 토스의 React Native 컴포넌트를 설치한 것은 아니며, HTML·CSS·SVG로 만든 웹 화면에 공개 색상과 설계 원칙을 적용했습니다.

[토스 디자인 시스템 소개](https://toss.tech/article/toss-design-system)는 반복해서 해결해야 하는 화면 문제를 공통 기준으로 다루는 배경 자료입니다. 이 앱에서는 카드, 각주, 도움말 창과 간격을 화면마다 제각각 만들지 않고 공통 규칙으로 맞췄습니다. 지표의 성격을 질문형으로 설명하는 문구는 이 앱의 사용자 요구와 계산식에 맞춰 작성한 것입니다.

[목적에 맞는 인터랙션](https://toss.tech/article/interaction)을 참고하여 움직임은 내용의 등장과 선택 대상 확인에 사용했습니다. 사용자가 분석 문장을 읽는 동안 계속 움직이는 장식은 넣지 않았습니다. 아래의 시간·크기·이동량은 토스의 의무 규격이 아니라 현재 앱에서 선택한 값입니다.

이 문서는 실제 사용자 조사 결과를 새로 확보했다고 주장하지 않습니다. 가독성과 이해하기 쉬운 표현을 목표로 한 구현 의도와, 코드·테스트에서 확인한 동작을 구분합니다.

## 3. old 화면과 new 화면은 무엇이 다른가

| 항목 | old | new |
| --- | --- | --- |
| 첫 화면 | 산업 원형 노드 | 가로로 넓은 사각 타일 지도와 전체 섹터 링크 |
| 공통 시각 스타일 | 기존 글꼴·카드·색상 | Pretendard, 회색·파란색 중심의 공통 스타일 |
| 상단바 | 기존 구성 | 중앙 로고, 우측 시장 표기 생략, 낮춘 높이 |
| 로딩 | 기존 텍스트 안내 | 화면 영역을 미리 확보하는 스켈레톤 |
| 선택 피드백 | 기존 동작 | 단어·타일의 작은 확대와 주변 이동 |
| 원문 팝업 | 기존 중앙 dialog | 중앙 dialog에 짧은 등장 애니메이션 |

`old`는 과거 시점의 코드 전체를 고정한 복사본이 아닙니다. 동일한 데이터와 기능 코드에 기존 화면 스타일을 적용하는 방식입니다. 지표의 질문형 설명, 쉬운 도움말, 연한 파랑 출처 강조, 중복 브라우저 툴팁 제거처럼 공통 코드에 적용한 개선은 두 화면에서 함께 사용됩니다.

`dart_remote/ui_version.py`의 `page_bytes()`는 `old`일 때 원래 HTML을 반환합니다. `new`에서는 HTML에 화면 버전 표시를 넣고 `ui-new.css`, `ui-new.js`를 추가하며 로딩 영역을 스켈레톤으로 바꿉니다. 따라서 기존 HTML과 기능을 공유하면서 새 디자인을 선택할 수 있습니다.

## 4. 첫 화면: 타일 크기와 색에는 어떤 의미가 있는가

첫 화면은 전체 산업의 분기 지표와 AI 분석을 다시 생성하지 않습니다. 서버가 전달한 산업 목록과 저장 시세·요약 정보를 받아 타일을 그립니다. 타일과 하단 링크의 목적지는 모두 산업 분석 화면입니다. 첫 화면에는 기업 분석으로 바로 가는 카드를 두지 않습니다.

타일 크기의 재료는 해당 KRX 지수 전체 구성종목의 시가총액입니다. 분석에 사용하는 몇 개 기업의 시가총액 합계를 공식 전체 산업 규모로 대신하지 않습니다. 유효한 시가총액이 있는 산업만 타일 면적을 배정합니다.

`sectorTileLayout()`은 사각 공간을 가로나 세로로 나누어 겹치지 않는 타일을 만듭니다. 화면 폭이 750px를 넘으면 시가총액의 제곱근을 면적 가중치로 사용합니다. 실제 시가총액이 25배 차이 나면 표시 면적은 5배 차이가 나므로 작은 산업도 살펴보기 쉬워집니다. 750px 이하는 시가총액에 정비례합니다. 툴팁의 실제 시가총액은 바꾸지 않습니다.

배경 색은 산업 지수의 제공된 등락률 방향과 크기로 정합니다. 양수는 붉은 계열, 음수는 푸른 계열이며, 표시 산업 중 절대 등락률의 최댓값을 기준으로 색의 강도를 조절합니다. 값이 없으면 미확인 색을 사용합니다. 따라서 색은 공시 신호 점수나 AI의 투자 판단을 뜻하지 않습니다.

도표 아래의 “산업 간 표시 면적 차이를 완화했습니다.” 문구는 표시하지 않습니다. 다만 계산 방식은 접근성 설명과 이 문서에 남기고, 데스크톱 도표에는 짧은 “시가총액 기준” 안내를 둡니다.

### 작은 타일에서 글자를 표시하는 기준

섹터 이름의 기본 글자 크기는 타일 면적에 따라 14-26px 사이에서 계산합니다. 실제 공간이 부족하면 0.5px씩 줄여 최소 12px까지 허용합니다. 등락률은 항상 이름 글자 크기의 1.5배입니다. 두 글자를 같은 비율로 조정하므로 타일마다 글자 비율이 달라지지 않습니다.

너비가 45px 미만이거나 높이가 38px 미만이면 이름과 등락률을 숨깁니다. 그 이상의 타일은 먼저 이름 최대 두 줄과 등락률을 함께 넣어봅니다. 함께 들어가지 않으면 등락률을 숨기고 섹터명만 표시하며, 타일 높이에 맞춰 두 줄을 넘는 줄바꿈도 허용합니다. 이름만의 글자 크기를 별도로 조정해 최소 12px에서도 전체 이름이 들어가지 않을 때만 이름을 숨깁니다. 작은 타일의 최소 여백은 3.5px이고 높이가 100px 미만이면 두 글자 사이 간격은 3px입니다. 숨기는 기준은 단순 면적 하나가 아니라 글자가 들어가는지까지 포함합니다.

글자를 숨겨도 타일 자체는 산업 화면으로 가는 링크입니다. 마우스를 올리면 툴팁으로 산업명·등락률·시가총액·분석 대상 기업 수 등을 확인할 수 있고, 접근성 이름도 남습니다. 상세 툴팁은 마우스 입력을 받지 않도록 하여 다른 타일의 선택을 가로막지 않습니다.

### 전체 섹터 링크는 어떻게 작동하는가

타일 아래에는 작은 타일만이 아니라 전체 섹터의 이름과 등락률을 표시합니다. 목록 폭은 타일 지도 전체 폭과 같고, 항목을 넣을 공간이 부족하면 여러 행으로 배치합니다. 데스크톱은 최소 145px 기준으로 열 수를 조절하고, 750px 이하에서는 두 열을 사용합니다.

항목에 마우스를 올리거나 키보드로 초점을 맞추면 해당 타일에 파란 테두리만 표시합니다. 벗어나면 강조가 해제됩니다. 하단 링크에서는 타일 툴팁을 표시하지 않으며, 툴팁은 타일 자체에 마우스를 올리거나 초점을 맞출 때만 표시합니다. 클릭해서 강조 상태를 고정하는 기능이나 `aria-pressed` 상태는 사용하지 않습니다.

항목은 타일과 같은 `href`를 가진 일반 링크입니다. 클릭하거나 Enter를 누르면 해당 산업 분석 화면으로 이동하며 새 탭으로 열기도 가능합니다. 시가총액이 없어 타일을 만들 수 없는 산업도 목록 링크로 접근할 수 있지만 강조할 타일은 없습니다. 크기 변경만 일어났을 때 목록을 재생성하지 않아 키보드 초점이 불필요하게 사라지지 않습니다.

## 5. 산업·기업 화면은 어떤 순서로 읽는가

| 순서 | 산업 화면 | 기업 화면 |
| --- | --- | --- |
| 상단 | 산업명과 안내 | 기업명과 사업 설명 |
| 첫 카드 영역 | 해당 KRX 지수, 공시 워드클라우드 | 해당 기업 주가, 기업 공시 워드클라우드 |
| 그 아래 | AI 산업 인사이트와 문장별 각주 | AI 기업 인사이트와 문장별 각주 |
| 상세 진입·요약 | 분석 대상 기업 카드 | 해당 기업의 최근 분기 지표 요약 |
| 재무 흐름 | 여러 기업의 분기별 지표 | 해당 기업의 분기별 지표 |
| 마지막 비교 | 기업 한눈에 비교 표 | 별도 기업 비교표 없음 |

기회·위험 등을 별도 카드로 나열하기보다는 검증된 AI 인사이트를 중심으로 읽게 합니다. 공시 설명의 생성 기준은 [03 인사이트 생성](03_인사이트생성과프롬프트.md)에 있습니다. 기업 화면의 “공시에서 살펴본 내용”은 별도 영역으로 표시하지 않습니다.

XML로 대체한 지표가 있으면 안내를 주요 재무 지표 흐름의 공통 기준 문구 아래에 둡니다. 기본은 접힌 상태이며 사용자가 펼쳐 대상 기업·분기 정보를 확인합니다. “CAPEX 비교 기준 확인 중 · N개 기업·분기”와 기존 분석 대상 5개 기업 자료 준비 안내는 표시하지 않습니다. 수치 자체의 누락·추정 상태를 정상 수치로 바꾸는 것은 아닙니다.

## 6. 색상을 같은 의미에 맞게 사용하는 방법

| 역할 | 현재 new 색상 또는 기준 | 의도 |
| --- | --- | --- |
| 배경 / 카드 | `#f9fafb` / `#ffffff` | 영역을 나누되 강한 장식을 줄임 |
| 제목 / 본문 | `#191f28` / `#4e5968` | 읽어야 할 내용에 시선이 머물게 함 |
| 보조 설명 / 테두리 | `#6b7684` / `#e5e8eb` | 본문과 설명의 위계 구별 |
| 조작 / 부드러운 배경 | `#1b64da`, `#3182f6` / `#e8f3ff` | 선택·이동할 수 있는 요소 구별 |
| 원문 근거 강조 | `#e3edf9` | 문서 안의 참고 위치를 연한 파랑으로 표시 |
| 지수·주가의 선 | 양수 `#e42939`, 음수 `#2272eb`, 0·미확인 `#6b7684` | 표시된 전일 대비 등락의 방향 전달 |

시장 선의 색은 전체 그래프 추세가 아니라 화면에 표시하는 전일 대비 등락 값으로 결정합니다. 타일의 색 강도와 시장 선의 색은 서로 다른 구현입니다.

### 워드클라우드: 다양하지만 흐릿하지 않은 12색

현재 `new` 워드클라우드는 아래 색을 표시 순서에 따라 순환합니다. 색 자체에는 긍정·부정·중요도 의미를 부여하지 않습니다.

```text
#396BA3  #79539C  #287F73  #A9573F  #4B70A1  #A04D76
#8D702F  #357665  #6253A0  #446F89  #9B672E  #414F61
```

차분한 색이 너무 흐릿하다는 피드백을 반영해 앞선 색보다 채도를 높이고 명도를 조금 낮췄습니다. 흰 배경과의 대비는 이 12색에서 최소 약 4.68:1입니다. 이는 색상 대비 계산 결과이며 화면 전체의 접근성을 모두 검증했다는 의미는 아닙니다.

### 재무 그래프: 기업을 구별하는 색

새 화면의 기본 기업 색은 `#AD646A`, `#527BA1`, `#9A7B3C`, `#4C8278`, `#82709D`입니다. 빨강·파랑·황토·초록·보라의 구분을 유지하며 채도를 조절했습니다. 서버가 기업의 `color`를 제공하면 그 값이 우선이고, 없으면 현재 선택 기업 순서대로 기본 색을 사용합니다. 산업·기업 화면을 오가도 모든 기업 색이 영구적으로 고정되는 전역 색상 레지스트리를 구현한 것은 아닙니다.

`old`의 단어·재무 그래프 기본 색은 유지합니다. 원문 강조색은 공통 코드에서 바꾸므로 두 버전 모두 연한 파랑입니다.

## 7. 워드클라우드의 크기와 배열은 왜 별도로 계산하는가

색을 바꾸는 일과 단어의 신호 강도를 계산하는 일은 구분합니다. 단어 선정, 표시 가중치, 불꽃 기준은 [04 워드클라우드](04_공시신호워드클라우드.md)의 계산 규칙을 사용합니다. 불꽃은 최근 공시 언급 증가를 뜻하며 주가 상승을 뜻하지 않습니다. 산업·기업 엔진의 불꽃 개수 제한이 모두 같다고 가정하지 않습니다.

브라우저는 `display_weight`에 따라 상대 글자 크기를 정하고, 같은 배율을 모든 단어에 적용해 겹치지 않는 큰 배치를 찾습니다. 마지막에는 SVG의 실제 글자·불꽃 경계를 측정해 가로·세로에 8px 여백을 남기는 공통 배율로 확대합니다. 상대 크기를 유지하며 영역을 활용하는 방식이므로 배열 비율에 따라 한 축에는 여백이 남을 수 있습니다. 빈 공간을 모두 없애기 위해 단어마다 크기를 다르게 늘리지 않습니다.

단어 선택은 마우스 클릭과 키보드 Enter·Space로 가능합니다. 선택하면 저장된 용어 해설·공시 설명·각주를 보여주고, 설명이 준비되지 않았으면 관련 공시를 살펴볼 수 있는 안내를 제공합니다. 화면을 열 때마다 모든 단어 설명을 새로 생성하지 않습니다.

## 8. 재무 그래프와 도움말을 이해하는 방법

지표 위에는 “성장”, “수익성” 같은 분류명 대신 질문을 표시합니다. 일반 기업은 “매출은 얼마나 성장하고 있나요?”, “팔아서 얼마나 이익을 남기고 있나요?”, “공장과 장비에 얼마나 투자하고 있나요?”, “투자하고도 현금이 남고 있나요?”입니다. 헬스케어의 연구개발 비율과 은행의 순이자이익·ROE·대손비용률 참고 지표·자기자본비율에는 각 지표에 맞는 질문을 사용합니다.

물음표 버튼은 한두 문장으로 의미와 예시 또는 주의점을 알려줍니다. 예를 들어 영업이익률 10%는 100원어치를 팔아 본업에서 10원의 이익을 남겼다는 뜻이라고 설명합니다. 계산식은 별도로 보여줍니다. 설명을 친절하게 바꾸었다고 투자 비율이 높을수록 무조건 좋다고 해석하지는 않습니다.

실제 설명은 서버의 `metricCatalog`가 우선입니다. `dart_remote/graph_metrics.py`의 `catalog()`가 산업별 설명을 만들고, 서버 카탈로그가 없으면 `data.js`의 기본 설명을 사용합니다. 문구를 수정할 때 화면 파일만 바꾸면 실제 화면에 반영되지 않을 수 있는 이유입니다.

선은 관측점을 연결한 꺾은선이며 모서리와 끝을 둥글게 처리합니다. 부드러운 곡선으로 보간해 없는 관측값을 만드는 방식이 아닙니다. 분기 % 지표의 표준편차가 300 이상이면 양수·음수와 0을 보존하는 로그 눈금을 사용합니다. 이는 단순 양수 로그가 아니며 표시 단위와 실제 수치는 바꾸지 않습니다.

산업 화면에서는 기업 범례를 클릭해 해당 선을 강조하고 다시 클릭해 해제할 수 있습니다. 현재 범례는 마우스를 올려 3개년 수치를 표시하는 동작이 아닙니다. 기업 화면은 한 기업만 표시하므로 범례를 숨깁니다. 재무 관측점을 가리키면 서비스 툴팁을, 선택하면 출처를 보여줍니다. 브라우저 기본 SVG title 툴팁을 추가하지 않아 같은 설명이 중복되지 않습니다.

자료가 한 지점만 없고 그 전후에 값이 있으면 해당 기업 색의 점선으로 연결합니다. 점선은 추정 수치를 계산한 것이 아니며 누락 위치의 안내로 구분합니다. 연속 두 지점 이상 누락이나 시계열 가장자리 누락은 연결하지 않습니다. 기업 화면의 표시 시작과 매출 지수 기준 분기는 [05 재무 지표](05_재무지표와원문출처.md)를 따릅니다.

지수·주가 그래프는 추세만 전달하므로 관측점과 상세 툴팁을 표시하지 않습니다. 재무 그래프의 관측점·출처 기능과 구분해야 합니다.

## 9. 각주와 원문 팝업은 어떻게 표시하는가

AI 문장 옆에는 작은 각주 버튼을 표시합니다. 새 화면은 둥근 버튼과 파란색으로 읽을 수 있는 근거가 있음을 알리고, 모바일에서는 누르기 쉬운 크기를 확보합니다. 각주를 누르면 원문 조회 API로 근거 위치를 요청합니다. 디자인 코드는 출처를 새로 만들어 붙이지 않습니다.

원문 창은 오른쪽 패널이 아니라 화면 중앙의 dialog입니다. 배경을 유지한 채 짧게 나타나며 긴 내용은 내부에서 스크롤합니다. 표가 확보되면 행·열·병합 셀을 가진 원본 표 형태로 표시하고, 문단 근거는 해당 위치를 강조합니다. XML 확보 여부·복구 검증 결과에 따라 읽을 수 있는 부분이나 안내를 표시하므로 모든 출처가 항상 완전한 전체 표로 반환되는 것은 아닙니다. 전체 문서는 DART 링크로 확인할 수 있습니다.

참고 위치는 연한 파랑 `#e3edf9`로 표시합니다. 화면 문단, 표의 대상 셀, iframe 내부의 전체·부분 복구 문서에 동일한 계열을 적용합니다. iframe 내부에는 바깥 화면 CSS가 직접 적용되지 않으므로 원문 HTML 생성 코드의 강조색도 함께 관리합니다.

## 10. 움직임과 로딩은 어떻게 절제하는가

| 상황 | 현재 동작 | 의도 |
| --- | --- | --- |
| 화면 내용 준비 완료 | 200ms, 약 8px 상승과 투명도 변화 | 내용이 준비됐음을 알림 |
| 지원 브라우저의 페이지 이동 | 150ms 전환, 상단바는 시각적 기준 유지 | 이동을 연결해 보이게 함 |
| 원문 창 열기 | 220ms, 약 12px 상승과 0.98배에서 1배 확대 | 별도 창의 등장 전달 |
| 단어·타일 첫 등장 | 260ms, 4-6px 이동, 작은 순차 지연 | 화면 구성의 등장 전달 |
| 단어·타일 가리키기 | 단어 약 2.5%, 타일 약 1.5% 확대 | 선택 대상 확인 |
| 주변 요소 이동 | 최대 약 4px, 가장자리에서 제한 | 강조를 보완하되 기본 배치 보존 |
| 자료 로딩 | 미리 확보한 카드·그래프 영역의 스켈레톤 | 화면의 큰 배치 변화를 줄임 |

워드클라우드에 마우스를 올릴 때 밑줄을 긋는 효과는 사용하지 않습니다. 본래 색을 유지한 작은 확대와 그림자로 강조합니다. 움직임은 점수나 데이터의 변화가 아닙니다.

스켈레톤은 서버가 첫 HTML을 보내는 단계부터 들어 있습니다. 홈·산업·기업마다 실제 화면의 큰 영역에 맞춰 배치하고, 성공하면 본문으로, 실패하면 오류 안내로 교체합니다. 기업 수와 문장 길이를 로딩 전에 모두 알 수 없으므로 최종 화면의 모든 픽셀 크기를 정확히 보장하지는 않습니다.

사용자의 움직임 감소 설정을 CSS와 JavaScript 양쪽에서 확인합니다. 이 설정에서는 등장·이동·스켈레톤 애니메이션을 끄며, 선택 테두리·내용·일반 페이지 이동은 유지합니다. 페이지 전환 기능을 지원하지 않는 브라우저도 보통의 링크로 이동할 수 있습니다.

## 11. 모바일과 데스크톱에서 달라지는 부분

상단바는 데스크톱 68px, 모바일 60px이며 로고는 중앙에 있습니다. 모바일에서는 산업·기업 상단 카드와 재무 그래프를 한 열로 배치합니다. 기업 카드는 가로로 살펴보는 구성을 사용하고 비교표는 표 영역 안에서 스크롤합니다.

새 화면의 타일 도표는 데스크톱 380px 높이이며 모바일에서는 화면 폭에 따라 240-310px 범위로 조절합니다. 상단 지수·워드클라우드 높이는 모바일에서 270px로 맞춥니다. 전체 섹터 목록은 모바일 두 열이며 이름이 길면 내용이 줄바꿈됩니다. 지표의 값이나 키워드의 상대 크기 가중치를 모바일에서 임의로 바꾸지는 않습니다.

## 13. 실행과 변경 반영

프로젝트 폴더의 PowerShell에서 새 화면을 실행하는 예입니다.

```powershell
& .\.venv\Scripts\python.exe -X utf8 app.py --ui-version new --prompt-version new
```

기존 화면은 `--ui-version old`입니다. 옵션과 `UI_VERSION`을 모두 생략하면 기본은 `old`입니다. `--prompt-version`의 `new`, `new2`, `old`는 표시할 분석 결과를 선택하므로 화면 버전과 독립적입니다. 예를 들어 새 디자인에 new2 보고서를 표시하려면 `--ui-version new --prompt-version new2`를 지정합니다.

Compose 배포는 서버 `.env`의 `UI_VERSION=new`를 설정하고 수정 파일을 업로드한 뒤 실행합니다.

```bash
docker compose up -d --build --force-recreate app
```

Compose를 사용하지 않는 직접 실행은 `python -m cloudapp.serve --ui-version new`입니다. 화면 변경에 보고서 재생성이나 DB 구조 변경은 필요하지 않습니다. Python 서버 코드나 시작 옵션을 바꿨다면 서버를 다시 시작하고 브라우저를 새로고침합니다. 정적 파일이 예전 상태로 남으면 강력 새로고침으로 확인합니다. 컨테이너의 기존 보고서 볼륨을 삭제할 필요는 없습니다.

시세 갱신 옵션은 디자인 선택과 별개입니다. 기존처럼 `--no-market-refresh`를 생략하면 시작 시 갱신을 시도하며, 시세 수집 범위·저장 정책은 [06 시세 수집](06_시세수집과화면.md)을 따릅니다.

## 14. 확인한 내용과 확인하지 않은 내용

현재 수정에서는 지표 계산·타일 면적·누락 구간·워드클라우드 배치·화면 버전·로컬 배포 동일성을 기존 테스트로 확인했습니다. 타일 목록의 전체 폭·줄바꿈, 마우스 올림·해제, 키보드 초점, 클릭 강조가 남지 않는 동작은 로컬 예시 화면에서 브라우저로 확인했습니다. 예시 화면 자료는 실제 DB나 분석 보고서를 교체하지 않았습니다.

실제 네이버 서버에 최신 디자인을 업로드하거나 다양한 기기에서 사용자 조사를 수행한 결과를 뜻하지는 않습니다. 원격 DB·Gemini의 현재 상태도 이 문서 작성 작업에서 새로 점검한 것은 아닙니다.

유지보수 시에는 색의 의미, 글자 최소 크기, 단어 상대 크기, 누락 수치 처리, 원문 위치 연결을 먼저 보존하고 화면을 개선해야 합니다. 새로 제안하는 기능과 구현된 현재 기능을 문서에서 구분해야 다른 개발자가 예전 요청을 현재 동작으로 오해하지 않습니다.


## 2026-10-12 화면 자료의 최신 시점과 안내

재무 그래프·카드·비교표는 실제 값이 있는 최신 분기를 기준으로 구성한다. 뒤쪽의 빈 분기는 제거하고, 공통 최신 분기에 값이 없는 기업은 이전 값으로 대체하지 않는다. 디자인·색·팝업 동작은 유지한다. 현재 인사이트의 빈 결과·생성 예외 안내와, 제안 단계인 100자 미만 설명의 탐색 문구 교체는 구별한다. 후자의 자동 교체와 카드 제목 변경은 아직 구현되지 않았다. [06](06_시세수집과화면.md)과 [10](10_현재코드변경점과적용범위.md)을 참고한다.
