# 서비스 구조와 데이터 조회

확인 기준일: 2026-10-08. [문서 목록](README.md)

## 구현 의도

산업이 추가될 때 산업마다 데이터베이스와 분석 코드를 복제하지 않도록, 산업 구성기업을 찾는 부분과 재무·공시 데이터를 읽는 부분을 분리했다. 기업과 분석 기간은 현재 DB에 등록된 자료를 기준으로 정한다. 반도체 5사·3개년으로 고정한 초기 구조와 다르다.

## 코드의 역할

`snapdart/data_access`의 catalog·repository 등 일부 파일은 공통 `dart_remote` 기능을 가져오는 연결 계층이다. 로컬·배포의 모든 파일이 같은 것은 아니며, 서버와 명령 진입점은 각각의 실행 환경에 맞게 구성되어 있다.

## 어떤 데이터를 어디에서 읽는가

현재 서비스의 원천은 원격 MySQL이다. `data/financial.db`, `filings.db`, CSV, Qdrant를 읽어 분석하는 초기 경로는 현재 실행 경로가 아니다. 원본 JSON을 로컬 파일로 읽는 대신 그 자료에서 적재된 DB 행을 조회한다.

| 데이터 구분 | 주요 테이블·뷰 | 사용 목적 |
| --- | --- | --- |
| 산업과 기업 | krx_indices, krx_index_constituents, companies | 활성 산업과 현재 구성기업 선택 |
| 재무 수치 | standardized_financials, financial_facts | 매출·영업이익·현금흐름·CAPEX 등; 계정 별칭 보완 포함 |
| 공시 내용과 벡터 | filings, chunk_metadata, chunk_embeddings | 문서 정보, 검색 본문, 저장 임베딩 |
| 원본 공시 | filing_source_documents, chunk_source_documents | 인용 청크에 연결된 XML과 출처 위치 |
| 정합성·보유 현황 | data_versions, embedding_metadata, coverage | 현재 버전 검증, 모델 계약, 기업·연도별 자료 유무 |

이 표는 서비스가 읽는 주요 데이터의 역할을 정리한 것이다. 데이터 생성 담당자의 전체 스키마나 수집 프로그램 명세를 대신하지 않는다.

## 산업·기업·연도 결정

1. `data_versions`에서 현재 버전이 정확히 하나이고 검증 완료인지 확인한다.
2. `krx_indices.is_active=1` 산업을 읽는다. 현재 구성기업 중 운영 대상 기업이 있는 산업이 서비스 후보가 된다.
3. `krx_index_constituents.is_current=1`과 `companies.is_operational=1`을 기준으로 기업을 읽는다. 추가 기업은 DB 관계와 데이터 구축 상태가 준비되어야 한다.
4. 분석 연도를 지정하지 않으면 해당 산업의 현재 버전 `coverage`에 등록된 전체 연도를 사용한다. `--years`로 일부 연도를 지정할 수 있으며 없는 연도를 요청하면 오류를 낸다.
5. 산업별 검색 주제·표시 순서·소개 문구·공식 지수 코드의 보완 설정은 [config/sectors.json](../../config/sectors.json)을 참고한다. 새 산업에는 공통 검색 주제와 기본 문구가 적용될 수 있지만, 산업별 용어·지표의 적절성까지 자동 검증하는 것은 아니다.

등록된 기업 중 자료가 없는 기업은 분석 가능한 기업과 동일하게 취급하지 않는다. 화면에 연결되지 않은 기업과 일부 보고서의 자료 부족을 알린다. 현재 기업 수와 자료 범위는 실행 시점 DB를 확인해야 한다.

## 생성과 조회는 별도 과정

분석 명령은 재무 이력과 관련 공시를 읽고 워드클라우드를 계산한다. `--llm`이면 Gemini로 산업·기업 인사이트와 단어 설명을 생성한다. 지정하지 않으면 공시 발췌를 구성하며, 이를 AI가 생성한 해석으로 표시하지 않는다. 생성 중 DB 버전이 달라지면 결과 저장을 거절한다.

완료 보고서는 앱 저장소에 저장한다. 기본 로컬 위치는 `data/service/remote/`이며 `SERVICE_CACHE_DIR`로 바꿀 수 있다. 분석은 원천 MySQL에 쓰지 않는다. `SERVICE_GCS_BUCKET`을 설정한 환경에서는 일부 공통 결과 저장을 GCS로 처리할 수 있다. 벡터·모델 캐시와 기능별 LLM 캐시는 별도 경로를 사용할 수 있다.

웹 화면을 열거나 시세를 갱신하는 행위는 Gemini 분석 재생성을 뜻하지 않는다. 최초 화면은 산업 목록과 저장된 보고서·시세 상태를 읽는다. 보고서가 없거나 현재 DB 버전과 맞지 않는 경우 기존 AI 결과를 자동으로 덮어쓰지 않고 분석 재실행이 필요하다고 알린다.

## 적용 범위

현재 목적은 공시 기반 산업·기업 분석이다. 투자 메모, 지속 감시 에이전트, 매매 추천, 뉴스 수집, 원천 공시 다운로드·전체 재임베딩은 이 웹 서비스 실행 흐름에 포함되지 않는다. 새로운 DB 산업을 읽는 구조와 해당 산업에 적합한 지표·어휘를 설계하는 일도 구분해야 한다.
