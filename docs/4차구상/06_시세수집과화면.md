# 시세 수집과 화면

확인 기준일: 2026-10-08. [문서 목록](README.md)

## 구현 의도

산업의 전체 시장 규모와 최근 시장 움직임을 먼저 보고, 공시의 사업 신호와 기업별 재무 흐름으로 내려가도록 화면을 구성했다. 시장 데이터는 공시 분석과 별도 수집하며, 지수 전체와 분석 대상 기업 표본을 구분한다.

## 수집하는 시장 데이터

| 데이터 | 현재 수집 경로 | 기준 |
| --- | --- | --- |
| 개별 기업 종가 | FinanceDataReader의 NAVER:종목코드 | 실행일 당일 제외, 최근 실제 거래일 종가와 직전 거래일 비교 |
| 개별 기업 시가총액 | 네이버 주식 integration 조회 | 조회 시점 정보; 전일 종가 시점이라고 보장하지 않음 |
| 산업 지수와 전체 시가총액 | KRX Open API krx_dd_trd | 해당 지수의 일별 CLSPRC_IDX와 MKTCAP |

산업 지수의 조회 이름은 DB의 `krx_indices.index_name`에서 읽는다. 표시 식별자는 DB의 `official_index_code`를 우선하고, 없으면 `config/sectors.json`의 보완 코드 또는 DB의 산업 코드를 사용한다. 현재 설정 파일에는 반도체의 보완 설정이 있으며 모든 산업이 파일에 고정된 것은 아니다. 서비스에 실제 표시할 산업은 현재 DB의 활성 구성기업과 데이터에 따라 정한다.

`KRX_API` 환경변수는 KRX 요청의 `AUTH_KEY` 헤더에 사용한다. 현재 공식 지수 수집은 FinanceDataReader 내부 KRX 경로가 아니라 프로젝트의 KRX API 코드가 직접 수행한다. FinanceDataReader는 개별 주가 수집에 사용한다. 지수 이름과 응답 필드를 대조하며 API의 승인·가용 범위도 충족되어야 한다.

주말·휴일이면 달력상의 어제 값이 없으므로 그 이전의 마지막 두 거래일로 비교한다. 당일 데이터가 응답에 포함돼도 화면 종가에서는 제외한다. 산업 시가총액은 해당 지수의 전체 구성종목에 대한 공식 값이며 분석 대상 5사 시가총액 합으로 대체하지 않는다.

## 자동 갱신의 범위

로컬 `app.py`와 배포 `cloudapp.serve`는 기본 실행 시 시세 수집을 백그라운드에서 시작한다. `--no-market-refresh`이면 저장된 시세로 시작한다. 시세 실패 시 기존 자료를 보존하고 갱신 실패 상태를 기록한다. 서버 시작 과정에서 갱신하는 것이며, 현재 코드만으로 서버가 켜진 채 매일 특정 시각에 반복 실행하는 스케줄러가 생기지는 않는다.

로컬의 지수 전체 수집 경로는 약 3년의 일별 이력을 확보한다. 최신 종가만 갱신하는 경로도 따로 있다. 배포의 기본 최신 갱신은 이전 이력을 유지하면서 최근 두 거래일을 보완한다. 배포가 첫 실행에서 자동으로 지수 3년 전체 이력을 채우는 동작까지 같지는 않다. 개별 주가 화면용 이력은 최근 최대 65개 거래일이며 수집 시 약 120일의 달력 범위를 조회한다.

분석 명령 `--llm`은 시세 수집 명령이 아니다. 보고서 재생성과 종가 갱신은 각각 실행·저장되며 새 공시가 들어왔다고 시세나 분석이 모두 자동으로 바뀌는 것은 아니다.

## 화면의 흐름과 표시

첫 화면은 산업별 원형 노드를 표시한다. 크기는 지수 전체 시가총액, 색은 최근 종가 변동을 사용한다. 최초 화면에 기업 상세로 바로 가는 목록을 두지 않고 산업 화면에서 기업 카드로 이동한다. 기업 화면의 기업 이동 기능은 같은 산업 내 비교를 지원한다.

산업 화면은 지수·워드클라우드, AI 산업 인사이트, 분석 대상 기업 카드, 분기 재무 그래프, 기업 비교표로 이어진다. 기업 화면도 같은 흐름을 사용하되 기업 주가와 해당 기업의 자료를 보여준다. 용어의 `?` 설명은 정해진 지표 안내이며 Gemini를 매번 호출하지 않는다.

현재 재무 그래프는 매출 지수·영업이익률·매출 대비 CAPEX·FCF 비율이다. 자세한 계산은 [재무 지표 문서](05_재무지표와원문출처.md)에 있다. 범례의 기업을 선택하면 해당 선을 강조하고 지점 툴팁에서 실제 분기 금액과 원문 출처를 확인한다. 초기 시안의 연도 선택 버튼이나 범례의 3개년 금액 팝업을 현재 기능으로 설명하지 않는다.

비율 그래프 값의 표준편차가 300 이상인 경우 부호를 유지하는 로그 눈금을 사용한다. 음수·0이 있는 재무 비율에서 일반 로그를 쓰는 대신 값을 압축해 표시하며 실제 값을 바꾸지는 않는다. 매출 지수에는 이 조건을 적용하지 않는다.

## 화면 데이터와 API

브라우저의 `web/assets/data.js`는 `/api/project`를 요청한다. 최초 화면은 전체 산업의 저장 상태를 읽고, `?sector=...`가 있으면 해당 산업의 보고서·분기 수치·시세를 연결한다. 이전 `WC_NEW/data/project.json` 시안 파일을 런타임의 데이터 원천으로 사용하지 않는다.

| 필드 | 내용 |
| --- | --- |
| sectors | 산업 ID·이름, 지수 이력·수익률·시가총액, 분석 기업 ID, 보고서 가용 상태 |
| companies | 산업과 연결된 기업 ID, 종목코드·이름·소개, 주가, 분기 재무정보 |
| keywords | 계산된 단어 점수·크기·상승 신호와 저장된 설명 |
| aiInsight | 문장별 text와 source_refs가 있는 설명 객체 |
| periods | 분석 연도에서 만든 YYYY Q1-Q4의 시간축 |
| coverage | 자료가 없는 구성기업과 일부 보고서의 원천 자료 상태 |

주요 조회 API는 `/api/sectors`, `/api/reports`, `/api/financial`, `/api/search`이며 각주·표는 `/api/source`, `/api/revenue-source`, `/api/quarter-source`로 연결한다. 조회 API 자체가 브라우저 사용자의 요청마다 Gemini 인사이트를 재생성하는 구조는 아니다.
