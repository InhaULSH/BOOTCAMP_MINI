# 06. 시세 수집과 화면

[문서 목록](README.md) · 기준: 2026-10-08

## 이 문서에서는 무엇을 알아보는가

앞 문서까지는 DB에서 자료를 읽고 설명·단어·재무 지표를 준비하는 과정을 살펴보았다. 이번에는 사용자가 페이지를 열었을 때 이 결과가 어떻게 화면에 나타나는지 알아본다. 화면 위의 주가지수는 별도의 시세 자료이며, 아래의 사업 설명과 재무 그래프는 공시·재무 자료를 사용한다.

예시의 A기업 사업 문장과 숫자는 앞 문서의 가상 자료를 계속 사용한다. 실제 화면의 지수와 주가는 외부 시세 서비스에서 수집한 값이지, 이 예시 숫자나 Gemini의 설명에서 계산한 값이 아니다.

## 먼저 브라우저와 서버의 역할을 나누어 이해한다

브라우저는 사용자가 페이지를 보는 프로그램이다. 서버는 요청을 받아 필요한 파일과 데이터를 보내주는 프로그램이다. 로컬에서는 내 PC가 서버 프로그램을 실행하고, 배포에서는 클라우드 컴퓨터가 그 역할을 한다. 같은 PC에서 실행하더라도 브라우저와 서버의 역할은 구별된다.

브라우저가 받는 파일에는 화면의 제목·영역을 정하는 HTML, 크기·색·간격을 정하는 CSS, 자료 요청과 그래프 조작을 담당하는 JavaScript가 있다. DB는 이러한 화면 파일을 직접 만들어 보내지 않는다. Python 서버가 DB와 저장 보고서를 읽어 데이터를 정리하고, 브라우저의 JavaScript가 그 데이터를 화면에 넣는다.

데이터를 요청하는 정해진 창구가 API다. 현재 화면의 주요 창구는 `/api/project`다. 이 주소로 산업을 지정하여 요청하면 서버는 그 산업의 화면 자료를 반환한다. 반환 형식은 항목 이름과 값을 담은 JSON이다. JSON은 그래프 이미지가 아니라 그래프를 그리는 데 필요한 값과 문장의 묶음이다.

```text
사용자가 산업을 선택한다
  → 브라우저가 해당 산업의 자료를 API로 요청한다
  → Python 서버가 저장 보고서·DB 분기 수치·저장 시세를 정리한다
  → 서버가 JSON을 돌려준다
  → 브라우저가 카드·단어·그래프·각주 버튼을 그린다
```

## 첫째, 최초 화면에는 산업을 고르는 데 필요한 자료만 보낸다

사용자가 첫 화면을 열면 서버는 사용 가능한 산업 목록과 저장된 보고서·시세 정보를 읽는다. 이때 모든 산업의 모든 분기 수치를 꺼내거나 Gemini 설명을 다시 만들지 않는다. 산업을 선택하기 전부터 무거운 분석을 모두 수행할 필요가 없기 때문이다.

브라우저는 산업을 원형 노드로 보여준다. 노드의 색은 해당 공식 주가지수의 등락을 나타내고, 유효한 전체 지수 시가총액이 있으면 노드 면적이 그 규모에 비례하도록 크기를 정한다. 시가총액은 구성종목들의 시장 가치 합계다.

전체 시가총액 자료가 없으면 미수집 상태에 맞는 대체 크기를 사용한다. 이 크기는 산업 규모 비교값이 아니다. 분석 대상 몇 기업의 시가총액을 더해 공식 전체 지수 시가총액처럼 표시하지 않는다.

현재 첫 화면의 이동 대상은 산업 분석 화면이다. 기업 분석으로 가는 카드는 산업 화면 안에 있다. 이는 사용자가 산업을 먼저 살펴보도록 한 화면 흐름이며, 기업 주소를 직접 입력하는 것을 막는 접근 권한 기능은 아니다.

## 둘째, 산업을 선택하면 보고서와 분기 자료를 합친다

반도체 노드를 선택하면 브라우저는 반도체를 지정하여 화면 자료를 요청한다. 서버는 저장 보고서가 현재 자료 기준에 맞는지 확인하고, 그 보고서에 포함된 기업들의 분기 재무를 DB에서 읽어 붙인다. 시세는 별도로 저장한 자료를 연결한다.

반환 자료에는 산업 목록, 분석 기업 목록, 기업별 분기 금액, 저장 AI 인사이트, 워드클라우드 단어와 설명, 지수·주가 이력이 들어간다. 선택하지 않은 산업은 최소 목록 정보만 남긴다. 필요한 산업의 화면을 보여주기 위해 모든 산업의 재무를 한꺼번에 읽지 않도록 한 것이다.

현재 기준의 보고서가 없거나 자료를 읽을 수 없으면 화면은 준비되지 않은 이유를 표시한다. 페이지를 열었다고 보고서 생성을 자동으로 시작하지는 않는다. 보고서 생성과 페이지 조회를 분리했다는 [README의 설명](README.md)이 여기서 실제 화면 동작과 연결된다.

## 셋째, 주가지수와 개별 주가는 별도 자료로 연결한다

산업 화면은 DB에 등록된 지수명에 맞는 공식 KRX 지수를 사용한다. 반도체 기업 몇 개의 평균 주가로 만든 대체 지수가 아니다. 현재 공식 지수의 종가와 전체 시가총액은 KRX OPEN API로 수집한다. 개별 기업 종가는 FinanceDataReader를 통해 네이버 시세를 읽는다.

표시 기준은 한국 날짜로 실행일 이전의 가장 최근 실제 거래일 종가다. 주말과 공휴일에는 달력상 어제의 종가가 없을 수 있다. 예를 들어 월요일에는 보통 금요일 종가를 보여주고, 목요일 종가와 비교한 등락률을 표시한다.

시세 수집은 기본적으로 웹 서버 시작 시 뒤에서 한 번 실행된다. 서버를 열자마자 갱신이 끝났다는 보장은 없고, 수집 실패 시 저장 자료를 유지할 수 있다. 자료에 표시된 기준일을 확인해야 한다. 서버가 계속 켜져 있는 동안 매일 정해진 시간에 다시 수집하는 스케줄러는 현재 없다.

로컬과 배포 모두 최초 갱신 시 실행일 전일부터 역산한 최근 3년의 지수 이력을 수집한다. 처음에는 이틀치 기록만 있더라도 미처리된 과거 날짜를 채운다. 이후에는 새 날짜와 최근 7일 범위의 미게시·정정 가능 날짜를 확인한다. 이미 처리한 과거 날짜를 매번 API로 다시 조회하지 않는다. 초기 수집은 시간이 걸리며 완료 전에는 기존 화면 자료가 유지된다.

## 넷째, 백엔드가 섹터별 지표를 계산하고 브라우저가 그린다

서버가 보내는 재무 자료에는 A기업의 2025년 4분기 매출 150억원, 영업이익 15억원, CAPEX 20억원, 영업활동현금흐름 30억원 같은 값이 들어갈 수 있다. 이 숫자는 앞 문서에서 제시한 가상 예시이며, 실제 전송 값은 원 단위 기준으로 정리한다.

백엔드의 `graph_metrics.py`가 분기 금액과 비교 기간을 맞추고 섹터별 지표를 계산한다. 가상 A기업의 전년 동분기 매출이 120억원이면 성장률은 25%, 영업이익률은 10%, CAPEX / 매출액은 약 13.3%, FCF Margin은 약 6.7%다. 브라우저는 서버가 보낸 `financials[].metrics`를 읽어 그래프를 그린다. Gemini가 그래프 좌표나 비율을 작성하지 않는다.

헬스케어는 세 번째 슬롯이 R&D / 매출액이며, 은행은 순이자이익 성장률·ROE·대손비용률 proxy·자기자본비율로 바뀐다. 성장률은 전년 동분기 대비이고 다른 지표는 분기 비율이다. 필요한 비교 값이나 분모가 없으면 0이나 다른 기간의 값으로 채우지 않는다.

산업 요약 수치는 최신 공통 분기에 계산 가능한 기업들의 중앙값이다. 중앙값은 숫자를 작은 순서로 정렬했을 때 가운데 값이다. 가상으로 영업이익률이 8%·10%·12%이면 요약은 10%다. 기업 수가 짝수이면 가운데 두 값의 평균을 사용한다. 기업 화면은 기업 하나의 값을 보여준다.

따라서 현재 요약 수치는 대표기업 지표의 합이나 지수 비중 가중평균이 아니다. 누락값은 계산에서 빠지며, 제외 기업 명단이 화면의 모든 곳에 자세히 표시되는 것은 아니다.

## 다섯째, 그래프와 설명을 사용자가 살펴볼 수 있게 한다

기업별 선은 서로 다른 색으로 그린다. 범례의 기업 버튼을 클릭하면 그 기업의 선을 앞으로 올리고 다른 선을 약하게 표시한다. 현재는 범례에 마우스를 올리는 방식이 아니라 클릭 강조 방식이다.

그래프의 점에 마우스를 올리거나 키보드로 초점을 맞추면 기업·분기·그래프 값과 실제 금액을 작은 창에서 확인한다. A기업의 매출 성장률 25%를 보면서 실제 4분기 매출 150억원도 함께 확인할 수 있다는 뜻이다. 은행 툴팁은 지표 값과 CFS·OFS 기준을 표시하며 절대금액 비교를 강조하지 않는다. 점을 클릭하거나 Enter/Space로 선택하면 수치 출처 요청이 이어진다.

없는 수치는 0으로 넣지 않고 선이 끊긴 구간으로 남긴다. 일부 비율이 매우 크거나 작은 경우에는 음수와 0을 함께 표시할 수 있는 로그 변환을 적용한다. 실제 숫자를 바꾸는 것이 아니라 화면상 거리를 조정하는 기능이며, 자세한 조건은 뒤의 구현 상세에 정리했다.

AI 인사이트는 저장한 문장을 표시하고 각주는 작은 번호 버튼으로 만든다. 워드클라우드는 코드가 전달한 표시 가중치로 배치한다. 변경된 산업/기업 선정 기준은 [04](04_공시신호워드클라우드.md)를 따른다. 글자 크기와 불꽃을 보고 사업 성과가 확정됐다고 해석하지 않도록 설명과 원문 확인을 함께 제공한다.

## 여섯째, 기업이나 출처를 선택하면 필요한 자료만 더 읽는다

산업 화면의 기업 카드를 누르면 해당 산업 안의 기업 분석 화면으로 이동한다. 기업 화면에서도 같은 산업의 자료를 요청하되 선택 기업을 중심으로 그래프와 설명을 구성한다. 현재 기업 화면에서는 상단의 산업분석 링크로 돌아가 다른 기업 카드를 선택할 수 있다.

수치의 점을 누르면 `/api/quarter-source`로 해당 기업·분기·지표를 요청한다. AI 문장의 각주를 누르면 `/api/source`로 저장 근거를 요청한다. 서버는 [05](05_재무지표와원문출처.md)의 원문 연결을 따라 필요한 자료를 돌려준다.

이 요청들은 산업 페이지 전체를 다시 생성하는 작업이 아니다. 이미 표시한 결과의 상세 자료를 읽는 작업이다. 다만 같은 원문 문장이 여러 위치에 있어 인용 위치를 확정하기 어려운 경우에는 별도 Gemini 후보 평가가 실행될 수 있다.

## 화면을 이해할 때 구별할 세 가지 기준

지수와 주가는 거래일 시세다. 재무 그래프는 선택 기간의 개별 분기 실적이다. AI 설명은 연간·최신 누적 자료와 공시 문장을 종합한 결과다. 세 자료는 갱신 시점과 표현 기준이 다르다.

이 기준을 구별하면 “오늘 주가가 올랐으므로 AI 설명도 오늘 새로 작성되었다”거나 “그래프의 한 분기 변화를 AI가 그대로 해석했다”고 오해하는 일을 줄일 수 있다. 서버는 각 자료를 연결하여 보여주지만, 서로 다른 자료를 같은 값으로 대체하지 않는다.

## 구현 상세: 파일과 정확한 처리 기준

앞부분의 흐름을 이해한 뒤 필요한 항목을 찾아 읽는 참고 영역이다. 처음 읽을 때 모든 함수명과 설정값을 외울 필요는 없다.

### 구현 의도: 시장 움직임과 공시 사업 흐름을 구별해 보여준다

첫 화면은 산업을 발견하는 원형 노드 화면이고, 산업 화면에서 기업 분석으로 이동한다. 시장 규모·가격 움직임은 시세 자료, 사업 설명은 공시와 재무 자료에서 가져온다. 대표기업 몇 개의 평균 주가를 공식 산업 지수처럼 보이게 하지 않는다.

웹 화면은 저장된 인사이트를 빠르게 읽고, 재무 흐름과 원문을 확인하는 역할이다. 조회할 때마다 Gemini로 같은 보고서를 재생성하거나 샘플 자료로 빈 값을 채우지 않는다.

### 산업 지수와 시가총액은 어디에서 오는가

공식 지수는 DB `krx_indices.index_name`에 대응되는 **KRX OPEN API** 일별시세정보에서 읽는다. 인증은 `KRX_API`이며 현재 URL은 `https://data-dbg.krx.co.kr/svc/apis/idx/krx_dd_trd`다. 요청에 `basDd` 날짜를 넣고, 응답에서 정확한 `IDX_NM`을 고른다.

`CLSPRC_IDX`는 지수 종가, `MKTCAP`은 해당 지수 전체 구성종목 시가총액이다. 응답의 날짜, 양수 종가·시가총액을 확인한다. 예를 들어 반도체는 DB에 등록된 KRX 반도체 지수를 사용하며, 헬스케어·철강·추가 산업도 등록 지수명을 읽는다. 고정된 기업 평균으로 지수를 만들지 않는다.

한 날짜의 응답에 여러 지수가 있으므로 날짜 JSON 캐시를 여러 산업에서 공유한다. 공통 이력 수집은 실행일 이전의 최근 3년 범위를 날짜별로 확인하고, 마지막 두 거래일로 등락률을 계산한다. 주말은 생략하고 공휴일·미게시일은 실제 응답으로 판단한다.

공통 `dart_remote.krx_market.collect_history()`가 로컬과 배포 모두 최초 3년치 이력을 채우고 날짜별 진행 상태를 저장한다. 다음 실행에서는 미처리 날짜와 최근 7일만 확인하며, 양쪽의 최초 이력과 최신 종가·전체 시가총액 기준이 동일하다.

### 개별 주가와 전일 종가의 의미

개별 종목은 FinanceDataReader의 `NAVER:종목코드`로 최근 약 120일 종가를 읽고 최대 65개 거래일 이력을 보관한다. 종목 시가총액은 네이버 종목 정보에서 읽는다. 현재 공식 KRX 지수를 FinanceDataReader로 수집하는 경로와 혼동하지 않는다.

종가 정리 함수는 한국 날짜 기준 실행일의 행을 모두 제외하고, 이전의 유효한 두 거래일을 사용한다.

```text
표시 가격 = 실행일 이전의 가장 최근 거래일 종가
전일 대비(%) = (그 종가 / 바로 전 거래일 종가 - 1) × 100
```

월요일 실행이면 일반적으로 금요일 종가와 목요일 종가를 비교하고 공휴일이면 더 이전 실제 거래일을 사용한다. 화면의 “전일”은 달력상 어제와 언제나 같지 않다.

KRX 전체 시가총액은 해당 지수 종가와 같은 응답 날짜의 자료다. 개별 종목의 네이버 시가총액은 별도 정보 요청이므로 과거 종가와 정확히 같은 시점의 시가총액이라고 보증하지 않는다. 종가 통일과 시가총액 시점 통일은 다른 문제다.

실패 시 저장 자료가 있으면 `stale` 표시와 오류 정보를 붙여 유지한다. 저장값이 있다고 오늘 기준 최신 데이터가 되는 것은 아니다. `dashboard`에서도 당일 행을 다시 제거해 오래된 장중 자료가 재노출되는 것을 줄인다. 코드와 다른 지수의 저장 자료는 사용하지 않는다.

### 언제 자동 수집하는가

로컬 `app.py`는 `--no-market-refresh`가 없으면 서버 시작 시 백그라운드 스레드로 운영 산업들의 개별 종가와 지수를 갱신한다. 배포 FastAPI도 시작 시 갱신하며 `--no-market-refresh` 또는 `NO_MARKET_REFRESH=1`로 생략한다.

서버 시작 시 한 번의 자동 실행이다. 서버가 며칠 계속 켜져 있다고 매일 정해진 시간에 자동 갱신하는 스케줄러는 현재 없다. 보고서 생성 명령도 시세 갱신을 대신하지 않는다. 외부 수집 실패가 보고서 생성과 같은 실패인지 구별한다.

최근 DART 목록을 수집하는 별도 함수는 남아 있지만 기본 `refresh_prices` 시작 경로가 그 함수까지 실행하지는 않는다. 공시 목록 수집과 공시 기반 인사이트의 분석 자료 갱신도 같은 기능이 아니다.

### 첫 화면은 전체 산업의 무거운 분석을 읽지 않는다

`/api/project`에 산업을 지정하지 않으면 산업 목록과 저장된 보고서·시세 스냅샷으로 노드를 만든다. 모든 산업의 재무 이력과 분기 수치를 조회하거나 보고서를 재생성하지 않는다. 다만 산업 목록 자체는 현재 DB를 읽으므로 완전한 오프라인 정적 페이지는 아니다.

노드 색은 해당 공식 지수의 등락과 화면 안의 등락 범위로 정한다. 유효한 시가총액의 노드 지름은 최대 노드 지름에 `sqrt(해당 시가총액/최대 시가총액)`을 곱한다. 따라서 면적이 시가총액에 비례한다. 최대 크기는 화면 공간과 노드 간 거리로 제한한다.

전체 시가총액이 없으면 대표기업 시가총액 합계로 대체하지 않는다. 미수집 상태를 표시하는 대체 크기를 사용하므로 그런 노드의 면적에는 규모 비교 의미가 없다. 현재 프런트는 이미 구성종목 시가총액 배열이 전달되는 경우도 처리하지만 기본 백엔드 계약은 공식 전체 시가총액이다.

첫 화면의 이동 링크는 산업 분석이다. 기업 카드는 산업 인사이트 아래에서 접근한다. 기업 URL 직접 입력이 기술적으로 금지된 것은 아니며, 이 이동 구조는 사용자 흐름이지 접근 권한 통제가 아니다.

### 산업·기업 화면용 JSON 계약

산업을 지정한 `project()`는 선택 산업의 보고서를 읽고 기업별 분기 자료를 붙인다. 다른 산업은 목록 정보만 남겨 조회 비용을 줄인다. 선택 산업에서 자료가 준비되지 않으면 `status='unavailable'`을 전달하고 화면은 이유를 표시한다.

| 화면 필드 | 내용 |
| --- | --- |
| `sectors[].analysisCompanyIds` | 해당 분석 보고서의 기업 ID 목록 |
| `companies[].id` | `산업ID:종목코드` 형태로 산업 간 기업 중복 구별 |
| `metricCatalog` | 4개 슬롯의 제목·역할·계산식·도움말·% 단위; 산업과 기업에 제공 |
| `companies[].metricProfile` | `industrial`·`health`·`bank`: 툴팁과 출처 요청 분기 |
| `financials[]` | `period`, `basis`, `metrics`; 일반 기업은 매출·영업이익·CAPEX·영업현금흐름, 헬스케어는 `rd`, 은행은 순이자이익·순이익·신용손실비용·잔액·평균 잔액 |

현재 `businessSummary`는 설정 프로필 또는 기본 설명이다. `metricInsights`, `disclosureSummary`를 표시할 자리는 있지만 현재 보고서 생성기가 항상 그 전용 설명을 생산하는 것은 아니다. 화면에 자리나 문구가 있다는 이유로 별도의 Gemini 생성 기능이 구현됐다고 해석하지 않는다.

### 현재 그래프와 요약 수치의 산식

| 산업 | 성장 | 수익성 | 투자 또는 건전성 | 여력 또는 자본여력 |
| --- | --- | --- | --- | --- |
| 반도체 | 매출 성장률 | 영업이익률 | CAPEX / 매출액 | FCF Margin |
| 자동차 | 매출 성장률 | 영업이익률 | CAPEX / 매출액 | FCF Margin |
| 헬스케어 | 매출 성장률 | 영업이익률 | R&D / 매출액 | FCF Margin |
| 철강 | 매출 성장률 | 영업이익률 | CAPEX / 매출액 | FCF Margin |
| 은행·금융지주 | 순이자이익 성장률 | ROE | 대손비용률 proxy | 자기자본비율 |

| 지표 | 분기 기준 산식 |
| --- | --- |
| 매출 성장률 | (현재 분기 매출액 / 전년 동분기 매출액 − 1) × 100 |
| 영업이익률 | 분기 영업이익 / 분기 매출액 × 100 |
| CAPEX / 매출액 | 분기 CAPEX / 분기 매출액 × 100 |
| R&D / 매출액 | 분기 연구개발비 / 분기 매출액 × 100 |
| FCF Margin | (분기 영업활동현금흐름 − 분기 CAPEX) / 분기 매출액 × 100 |
| 순이자이익 성장률 | (현재 분기 순이자이익 / 전년 동분기 순이자이익 − 1) × 100 |
| ROE | 분기 순이익 × 4 / 평균 자기자본 × 100 |
| 대손비용률 proxy | 분기 신용손실비용 × 4 / 평균 대출채권 × 100 |
| 자기자본비율 | 분기 말 자본총계 / 분기 말 자산총계 × 100 |

은행의 평균 자기자본·평균 대출채권은 직전 분기 말 잔액과 현재 분기 말 잔액의 산술평균이다. 1분기에는 전년 말 잔액이 필요하다. 연환산은 분기 순이익·신용손실비용을 4배 하는 방식이며 연간 실적 예측을 뜻하지 않는다. 금융지주 4개사는 CFS, 카카오뱅크는 OFS로, `company_financial_profiles`에 등록된 기준과 비교 범위를 사용한다. 다른 기준의 금액을 섞지 않고 성장률·비율을 비교한다. 순이익은 `NET_INCOME`을 사용한다. 자기자본비율은 자본총계 / 자산총계이며 CET1·BIS 비율이 아니다. NIM·CET1·NPL·연체율은 이번 그래프에서 제외한다.

비율의 분모와 성장률의 전년 동분기 값은 양수여야 한다. 첫 표시 분기를 100으로 삼는 매출 지수는 더 이상 사용하지 않는다. 전년 동분기 자료가 없으면 그 분기의 성장률만 비운다. 모든 지표는 %이며, 평균 잔액이 필요한 지표는 직전·현재 두 잔액이 모두 있어야 한다.

내부 슬롯 키 `revenue`·`operating`·`capex`·`fcf`는 기존 배치를 유지하기 위한 이름이다. 은행의 `capex` 슬롯 값은 CAPEX가 아니라 대손비용률 proxy이며, `fcf` 슬롯은 자기자본비율이다. 제목·계산식·도움말과 출처 요청은 서버의 `metricCatalog`와 `metricProfile`을 따라 바뀐다. 최초 응답에 원천 출처 행 전체를 전송하지 않으며, 클릭 시 별도 출처 요청으로 읽는다.

요약값은 산업 화면에서 공통 최신 분기에 유효값이 있는 기업들의 중앙값이다. 기업 화면에서는 해당 기업의 최신 분기 값이다. 대표기업 수치의 단순 합이나 지수 비중 가중평균이 현재 화면 요약은 아니다. 서버 `dashboard`에는 과거 연간 가중 지표를 위한 필드가 남아 있어도 현재 `app.js` 요약에 사용하지 않는다.

AI 인사이트는 연간 이력과 최신 누적 공시를 종합한 설명이고, 아래 그래프는 개별 분기다. 화면에 이 차이를 표시한다. 분기 수치 하나의 변화를 AI가 직접 해석한 전용 설명이라고 간주하지 않는다.

### 그래프 가독성과 사용자 조작

그래프는 SVG 꺾은선·점으로 그린다. 결측은 0으로 바꾸거나 선으로 건너 연결하지 않는다. 산업 화면은 기업별 색을 고정하며 범례 버튼을 클릭하면 선택 기업의 선을 앞으로 올리고 다른 선은 약하게 만든다. 초기에는 첫 기업이 선택돼 있다.

현재 범례는 클릭 강조 방식이며 예전의 범례 마우스 이동 팝업이 아니다. 선택한 기업을 다시 클릭하면 전체 기업의 선을 선명하게 표시한다. 다른 기업을 선택한 동안 비선택 선의 불투명도는 16%다. 지점에 마우스를 올리거나 키보드로 초점을 맞추면 해당 기업·분기·그래프 값과 일반 기업의 실제 금액 툴팁이 나온다. 헬스케어 투자 슬롯의 금액은 R&D이며, 은행은 절대금액 대신 재무 기준을 표시한다. 클릭 또는 Enter/Space로 분기 수치 출처 창을 연다. 연도 선택 버튼은 없다.

퍼센트 단위 분기 그래프에서 유효값 전체의 모집단 표준편차가 300 이상이면 부호 보존 로그 변환을 사용한다.

```text
변환(v) = sign(v) × log(1 + abs(v)/10)
```

음수·0·양수를 함께 표현하기 위한 것이며 일반 로그와 다르다. 데이터 값을 바꾸는 것이 아니라 화면 좌표만 바꾼다. 현재 임계값 300은 해당 그래프에 표시된 유효 퍼센트 값의 표준편차다. 이제 매출·순이자이익 성장률도 %로 표시하므로 같은 조건이 적용된다. 다른 비율 그래프를 다시 전년 대비 변화율로 바꾼 뒤 표준편차를 계산하지는 않는다.

지수/주가 이력이 80개를 넘으면 화면에서는 월별 마지막 관측값으로 줄여 그리며 최신 종가를 유지한다. 저장 시계열 전체를 지워 월별로 바꾸는 기능은 아니다. 시장 차트와 재무 차트 모두 현재 y축 범위에 0을 포함하는 구현이다.

### 화면 API와 오류·보안 경계

| API | 용도 |

| `/api/sectors` | 사용 가능한 산업 목록 |

| `/api/quarter-source` | 분기 수치와 계산 구성요소의 출처 |

웹 API에 보고서 생성 POST 경로는 없다. 관리자가 CLI로 생성한다. 다만 원문 위치가 모호한 각주 조회는 [05](05_재무지표와원문출처.md)의 Gemini 후보 평가 경로를 탈 수 있다.

화면은 문자열을 이스케이프하며 각주는 번호 버튼으로 표현한다. 원문 HTML은 제한된 요소와 sandbox iframe을 사용한다. 로컬 서버는 공개할 정적 파일을 목록으로 제한하고 기본 loopback에만 바인딩한다. 배포는 FastAPI의 예외 처리로 원격 접속 정보가 그대로 노출되지 않게 한다. 서비스 접근 인증이 이미 마련돼 있다는 뜻은 아니므로 공개 운영 환경의 접근 제어와 별개다.

자료 오류를 빈 샘플로 숨기지 않지만 모든 `stale`·개별 수치 누락 설명이 현재 화면의 모든 위치에 표시되는 것은 아니다. 예를 들어 산업 최신 중앙값은 유효값만 사용하는데 제외 기업 명단을 함께 상세 표시하지 않는다. API의 상태 필드와 실제 화면 표시 범위를 구별한다.

## 2026년 10월 10일: 지수 이력 수집과 최신 자료 보존

공통 구현은 `dart_remote/krx_market.py`의 `collect_history`, `daily`, `merge`다. 로컬의 `snapdart/market.py`와 배포의 `cloudapp/market.py`는 모두 이 경로를 사용한다. 지수명은 기존처럼 MySQL의 KRX 지수 등록에서 읽고, 지수 종가와 전체 구성종목 시가총액을 동일 기준일 응답에서 선택한다.

수집 범위는 한국 날짜 기준 실행일 전일부터 달력상 3년 전 같은 날까지다. 윤년의 2월 29일은 대응 연도의 2월 28일로 조정한다. 주말은 조회하지 않으며 공휴일·미게시 날짜는 빈 응답으로 처리한다. 날짜별 원본 응답은 `krx_api/daily_responses/YYYY-MM-DD.json`에 저장한다. 하나의 원본에는 여러 지수가 들어 있어 다른 섹터의 초기 수집에서도 재사용한다. 요청 사이에는 0.12초를 기다리고, 기존 HTTP 오류 재시도 정책을 유지한다.

지수별 진행 상태는 위 캐시 폴더의 `history/지수명SHA256.json`에 저장한다. 내부에는 실제 지수명과 날짜별 종가·전체 시가총액 또는 빈 응답 표시가 있다. 날짜를 처리할 때마다 임시 파일을 원자적으로 교체하여 저장하므로 중단되면 완료된 날짜 다음부터 재개한다. 최근 7일은 빈 응답을 확정된 휴장으로 보지 않고 다시 확인하며, 갱신 요청이 빈 응답이어도 이미 확보한 같은 날짜의 유효 원본을 버리지 않는다. 초기 수집 도중 실패하면 화면용 기존 시장 스냅샷은 보존하고 다음 실행에서 이어서 채운다.

병합은 최근 3년 범위 밖의 오래된 기록과 실행일 당일·미래 기록을 제외하되, 새 결과의 마지막 날짜보다 뒤에 있는 기존 과거 기록은 삭제하지 않는다. 새 결과가 기존 최신 기준일보다 오래되면 기존 최신 종가·등락률·동일 날짜 시가총액을 함께 유지하고 갱신 지연 표시를 붙인다. 다른 지수 코드의 기록은 섞지 않는다. API 수집은 진행 캐시를 채우고, 성공한 결과를 기존 시장 스냅샷에 병합한 뒤 화면의 `indexSeries`로 전달한다.

서버 시작 시 한 번 수집하는 방식은 그대로이며 매일 자동으로 실행되는 스케줄러를 새로 추가한 것은 아니다. 배포 코드를 서버에 반영하려면 이미지를 다시 빌드하고 컨테이너를 재생성한다. 첫 갱신은 `docker compose run --rm app python -m cloudapp.cli market --krx`로 명시적으로 실행할 수도 있다. 분석 재생성이나 Gemini 호출은 지수 수집에 필요하지 않다.

공식 API는 과거 일별 지수 조회를 제공한다. 날짜별 수집과 캐시 재사용으로 중복 호출을 줄인다. [KRX 서비스 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd), [KRX API 이용약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp).

## 화면 그리기와 전송 최적화 (2026-10-10)

연속된 화면 크기 변경과 글꼴 준비 이벤트는 브라우저의 다음 화면 갱신 시점에 한 번으로 합쳐 처리한다. 워드클라우드는 표시 영역의 가로·세로가 달라졌을 때만 재배치하고, 글꼴 로딩 완료 시에는 다시 배치한다. 그래프의 데이터 점, 기업 선택·해제, 흐림 효과와 원문 버튼 기능은 유지한다.

공개 HTML·JS·CSS·글꼴 파일은 브라우저가 보관하되 서버에 최신 여부를 다시 확인하도록 `Cache-Control: no-cache`를 사용한다. 로컬은 내용 기반 ETag와 조건부 요청으로 변경 없는 파일에 304를 반환하고, 배포는 StaticFiles의 정적 파일 조건부 요청을 이용한다. API 응답은 계속 `no-store`다. gzip을 지원하는 요청에는 1,024바이트 이상 응답을 압축한다. 로컬 공개 파일은 파일 상태를 확인하고 최대 32개·16MB에서 원본 또는 압축 결과를 재사용한다. 배포 압축은 Starlette GZipMiddleware를 사용한다.

압축 구현의 공식 참고 자료: [Starlette GZipMiddleware](https://www.starlette.io/middleware/#gzipmiddleware).
