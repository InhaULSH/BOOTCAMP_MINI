# 공시 검색과 벡터 검증

확인 기준일: 2026-10-08. [문서 목록](README.md)

## 구현 의도

사용자가 입력한 표현이 공시의 단어와 완전히 같지 않아도 관련 문구를 찾기 위해 BGE-M3 의미 검색을 사용한다. 기업·산업·기간을 먼저 제한해 다른 기업의 설명이 섞이는 것을 줄이고, 저장 벡터와 질문 벡터가 같은 기준인지 검사한다.

## 실제 검색 순서

예를 들어 반도체 산업에서 삼성전자의 특정 연도 사업보고서에 대해 “HBM 수요 변화”를 검색하면 다음 순서로 동작한다. 해당 기업과 연도의 자료가 DB에 있다고 가정한 예시이며 검색 결과를 새로 실행한 사례는 아니다.

1. 산업과 기업 식별자를 DB의 구성기업과 대조한다.
2. SQL로 기업, 연도, 보고서 종류, 현재 데이터 버전과 검색 가능 여부를 제한해 후보 청크를 읽는다. 분석 기능은 필요에 따라 사업 관련 섹션 조건도 추가한다.
3. 현재 임베딩의 모델·리비전·차원·정규화 여부와 청크·벡터 대응을 검사한다.
4. MySQL의 `chunk_embeddings`에서 확보한 벡터 스냅샷 중 해당 후보의 벡터를 고른다. 동일 버전의 검증된 로컬 캐시가 있으면 재사용한다.
5. 질문을 로컬 BGE-M3로 임베딩하고 정규화한다.
6. 후보 벡터 전체와 질문의 코사인 유사도를 계산해 상위 `top_k`개를 반환한다.
7. 청크 본문과 기업·연도·보고서·섹션·청크 ID·유사도 등이 검색 결과에 포함된다. 보고서 생성은 이 결과 중 입력 예산과 자연어 근거 조건을 만족하는 자료를 Gemini에 전달한다.

현재 기본 경로에는 키워드 상위 청크를 합쳐 질문 벡터를 만드는 과정이나 키워드 점수와 벡터 점수의 혼합이 없다. 질문 자체를 같은 모델로 임베딩해 비교한다. 유사도가 높다는 것은 관련성이 높다는 뜻이며, 요약을 직접 뒷받침하는 근거라는 판정은 별도로 수행한다.

## 모델과 검색 엔진

| 항목 | 현재 코드 기준 |
| --- | --- |
| 질문 모델 | BAAI/bge-m3 |
| 고정 리비전 | 5617a9f61b028005a4858fdac845db406aefb181 |
| 벡터 차원 | 1024 |
| 질문 입력 | 최대 8,000자 제한, 모델 최대 길이 8,192토큰 |
| Windows 기본 엔진 | NumPy로 정규화 벡터의 내적 계산 |
| Linux 기본 엔진 | FAISS IndexFlatIP로 후보 벡터의 내적 계산 |
| 선택 설정 | SEARCH_BACKEND=numpy, faiss, keyword |

FAISS는 현재 후보를 메모리의 인덱스에 넣어 정확한 내적 검색을 수행한다. 별도 원격 검색 서버 주소나 외부 `.faiss` 파일을 제공받아야 하는 실행 구조가 아니다. 산업별 FAISS를 따로 복제하지 않고 SQL에서 후보 기업을 제한한다.

`keyword`를 명시하면 단어와 일부 별칭의 본문 등장 횟수로 순위를 정한다. 기본 의미 검색의 실패 시 자동으로 keyword로 바꾸지는 않는다. keyword는 진단·호환 경로이며 BGE-M3 검색과 동일한 의미 검색 결과를 보장하지 않는다.

## 무엇을 검증하는가

`data_versions`의 검증된 현재 버전과 `embedding_metadata`의 현재 메타데이터가 각각 하나여야 한다. 메타데이터의 모델·리비전·1024차원·정규화 여부가 코드 계약과 같아야 하며, 검색 가능 벡터 수와 `faiss_ntotal`도 같아야 한다.

실제 청크와 벡터의 ID·활성 상태·버전·본문 해시·개수를 대조한다. 전체 대응 검사는 동일 계약에서 최대 30초간 재사용하며 버전이 바뀌면 즉시 다시 검사한다. 모델을 읽은 뒤 일부 저장 청크를 재임베딩해 일치 여부도 확인한다. 이 표본 검사가 모든 청크의 의미 정확도를 측정하는 것은 아니다.

벡터 스냅샷은 `DART_CACHE_DIR` 또는 기본 `.dart_cache` 아래에 버전과 계약을 반영해 저장된다. MySQL을 원천으로 사용하되 같은 벡터를 요청마다 다시 내려받는 비용을 줄이기 위한 캐시다. 질문 모델 캐시는 `BGE_M3_CACHE_DIR`, 실행 장치는 `BGE_M3_DEVICE`로 설정한다. 기본 장치는 CPU이며 이 경로가 Intel GPU를 자동으로 사용한다고 설명하면 안 된다.

## 오류와 한계

청크와 벡터의 개수·ID·버전이 다르면 불완전한 자료로 검색하지 않고 오류를 낸다. 이는 Gemini의 토큰 오류와 별개이며, 원천 DB의 청크·벡터·메타데이터를 같은 검증 완료 버전으로 동기화해야 한다. 캐시 삭제만으로 원천 데이터의 불일치를 고칠 수 없다.

BGE-M3는 의미가 비슷한 문구를 찾지만 동의어·다른 표현을 항상 찾는다는 보장은 없다. SQL 범위 밖의 문서나 DB에 없는 청크는 반환할 수 없다. 모델 계약 검증도 공시 해석의 정확도를 보장하는 검사는 아니다.
