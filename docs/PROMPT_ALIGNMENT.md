# 프롬프트 정의서와 현재 구현의 대조

2026-10-02에 `data_new/프롬프트 정의서.pdf`를 읽고 코드·JSON Schema·검증·전송·화면을 대조했다. 원본 PDF는 변경하지 않았다.

| 항목 | 정의서의 요구 | 현재 구현 |
| --- | --- | --- |
| 분석 근거 | 제공된 재무자료와 검색 공시만 사용 | 공통 지시문으로 전달하고 SQL·저장 벡터로 근거 선별 |
| 산업 인사이트 | 2-3문장, 두괄식, 변화·배경·의미 | 지시문과 문장 배열 개수 검증 |
| 공통 흐름 부족 | 기업별 차이 또는 근거의 한계 설명 | 공통·산업 지시문 그대로 적용 |
| 근거 개수 | 종류별 또는 문장별 할당 규칙 없음 | 수치 2개＋공시 1개 조건 없음. 기존 출처 최대 3개·최소 1개 제약 제거 |
| 기업명 개수 | 두 기업명을 반드시 쓰라는 규칙 없음 | 기업명 개수 검사 없음 |
| 글자 수·인과 표현 | 400자 제한·특정 단어 일괄 금지 없음 | 추가 제한 없음 |
| 자료 부족 | 확인 가능한 데이터가 부족함을 설명 | 공시 없이 재무자료만 있는 경우에도 설명 가능. 자료가 전혀 없으면 PDF의 부족 안내 문구 반환 |
| 입력 금액 | 없는 수치 생성·수정 방지 | 인용 근거 금액과 부호를 확인. 조·억·원 표현의 반올림 정밀도를 적용 |
| 중간 보고서 | 분기·반기 공시 및 재무자료 활용 | Q1·H1·Q3 누적 자료에도 독립된 근거 ID와 해당 보고서 출처 부여 |
| Gemini 설정 | temperature 1, 산업 500·키워드 300 출력 토큰 | 동일. top-p와 thinking level은 별도 지정하지 않음 |
| 기업 전용 규칙 | 미정. 기업 분석 목적만 기재 | 목적 문구 사용. 임의의 문장 수 상한 없음. 기존 짧은 카드의 500토큰 예산 유지 |
| 키워드 인사이트 | 1-2문장 설명 | 내부 프롬프트·분기는 동일. 전용 클릭 팝업은 현재 미구현이며 이번 통합에서 새 기능으로 추가하지 않음 |
| 결과 JSON | `industry_insight` 문자열 등 | 기존 문장별 각주 유지용 `sentences[{text, refs}]` 전송 구조 사용 |

공통·산업·키워드 지시문과 산업 사용자 요청의 문구는 PDF에서 추출한 내용과 공백·표기 차이를 정규화해 대조했고 일치했다. 2-3처럼 기간·범위 기호는 프로젝트 규칙에 맞춰 대시로 표기했다.

‘수치 2개＋공시 1개’ 조합을 강제한 코드는 없었다. 이전 화면의 해당 조합은 저장된 모델 응답의 선택이었다. 다만 출처 배열의 최대 3개 제한이 있었으므로 이를 제거했다. 이제 공시 근거만 4개 이상을 쓰는 문장도 허용하며, 부족 안내에는 출처를 억지로 붙이지 않는다. 입력에 없는 ID는 여전히 거절한다.

출력 JSON의 문장·각주 메타데이터는 이전에 요청한 원문 조회 기능을 보존하기 위한 차이이다. 산업 분석 내용을 추가로 강제하는 조건은 아니다. 정의서는 기업 전용 프롬프트·키워드 화면의 모든 세부 동작을 확정하지 않았으므로, 미정인 부분을 새 분석 규칙으로 채우지 않았다.

검증 코드는 문장 수, 형식, 실제 근거 ID, 일부 원화 금액을 확인한다. 모든 비율·기간·서술의 사실성이나 인과관계의 타당성을 자동 판정하는 코드는 아니다. 저장 JSON의 구조가 맞다고 서술 전체가 입증된 것은 아니다.

프롬프트 버전은 `bigin-pdf-v4`이며 기존 응답 캐시와 구분한다. 현재 게시 보고서는 보존했다. 새 조건으로 화면의 분석을 바꾸려면 통합 루트에서 실행한다.

```powershell
$env:LLM_PROVIDER = "gemini"
& .\.venv\Scripts\python.exe -X utf8 -m snapdart.analyze --refresh-llm --sector 반도체
```
