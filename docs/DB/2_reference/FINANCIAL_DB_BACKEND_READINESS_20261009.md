# Financial DB 백엔드 사용 가능성 최종 평가 (운영 v10)

- 작성일: 2026-10-09
- 검증 방식: 읽기 전용. 운영 SQLite·MySQL·staging·원본·벡터·KPI 백업을 바꾸지 않았다.
  - 백엔드 함수는 운영 DB 사본(`db/sandbox/backend_readiness/financial_v10_copy.db`)으로 실행했다.
  - MySQL은 SELECT만 실행했다.
- 근거 출력: `db/sandbox/backend_readiness/01~09_*.txt`

## 1. 최종 판정: **CONDITIONAL GO**

## 2. 판정 근거

**DB 자체는 정확하고 일관된다.**
- 핵심 재무값이 원천 API와 일치한다.
- 연결·별도 혼합, 단위 혼합, 중복이 없다.
- SQLite–MySQL 활성 데이터가 값 단위로 같다.
- 금융 비용 부호 정책이 정상 동작한다.
- 표본 시나리오 10건의 값이 모두 원천과 일치한다.

**그러나 조회 계층에 그대로 연결하면 틀리거나 빠진 답이 나오는 문제가 있다.**
- MySQL 표준 뷰에서 당기순이익이 전 기업에서 빠지고, 영업이익·영업현금흐름이 약 절반 빠진다(H1).
- 저장소 분석기가 실행 중에 현금흐름표 잔액 줄·자본변동표 행의 Q4를 만들어 낸다(H2).
- 에이치브이엠이 기본 조회에서 조회되지 않는다(H3).

**판정:** 중대 데이터 오류(NO-GO 사유)는 없다. 위 3건은 조회 조건이나 설정을 고치면 해소된다. 그래서 CONDITIONAL GO로 판정한다.
- 백엔드 팀 자체 코드는 저장소에 없어 실행 검증을 하지 못했다(NOT TESTED). 이 점도 조건부 판정의 이유다.

## 12. 반드시 수정할 항목과 개선 권장 항목

**인계 전 필수**(각 수정은 별도 승인)
1. **H1 — 데이터팀:** MySQL 표준 뷰가 `standard_account_mapping`(공식 태그 + 표 구분 → 24개 표준명)으로 조인하도록 바꾼다. 또는 사실값의 표준명을 공식 태그 기준으로 정규화한다. 재무 값은 바뀌지 않는다.
2. **H3 — 데이터팀:** 에이치브이엠 프로필(OFS, CAPEX 적용)을 추가한다. 프로필 없는 회사의 AUTO는 주 기준을 사실값에서 고르게 해도 된다.
3. **H2 — 백엔드:** 실행 시 Q4 계산을 손익계산서·현금흐름표의 흐름 계정으로 한정하고, 잔액 줄·자본변동표·주당이익은 제외한다. DB의 저장 분기만 쓰는 것을 권장한다.
4. **M1 — 백엔드:** `review_status != 'approved'` 행은 답변에 "검토 필요"로 표시하거나 제외한다.

**개선 권장**
- M2: "자본총계"는 BS 시점값만 사용
- M3: 지표 테이블 버전 관리, 반영 시간대 공지
- M4: 결과 상한 조정 또는 계정 필수화
- M5: 원문 재확인
- L1~L6

## 13. 백엔드 팀 데이터 사용 규칙

1. **값 선택:** `is_calculated=1`이면 `calculated_value`, 아니면 `normalized_value`를 쓴다(MySQL 뷰 `value`는 이미 선택됨). 단위는 원(KRW)이다.
2. **기간 구분**
   - 잔액은 `point_in_time`, 손익·현금흐름의 연간은 `annual`, 누적은 `cumulative`, 3개월은 `quarterly`다.
   - 분기 추이는 `quarterly`만 비교한다.
   - Q4는 FY 보고서의 `quarterly`(대개 계산값)를 쓴다.
3. **자본총계·현금 잔액:** 재무상태표(BS) `point_in_time`만 쓴다. 자본변동표·현금흐름표의 기초·기말 행을 차감하거나 합산하지 않는다.
4. **연결·별도:** 회사당 한 기준이다. 23개사는 CFS, 카카오뱅크·에이치브이엠은 OFS다. 한 질문에서 기준을 섞지 않는다.
5. **금융 5개사:** `financial_metric_values`를 쓴다.
   - 비용 지표의 `value`는 양수 = 비용, 음수 = 순환입이다. 절댓값 처리를 하지 않는다.
   - 공시 원값은 `source_values.sign_standardization.original_value`에 있다.
6. **검토 상태:** `review_status='review_required'` 행(현재 10행)은 확정값으로 쓰지 않거나, 쓸 때 반드시 표시한다.
7. **값이 없을 때:** 없는 값은 없다고 답한다. 0으로 채우거나 누적값끼리 빼서 만들지 않는다.
8. **MySQL 조회**
   - 활성 행(`is_active=1`)만 쓴다.
   - 순이익·영업이익·영업현금흐름은 H1이 해결될 때까지 `standardized_financials` 대신 `financial_facts`의 공식 태그로 조회한다. 공식 태그: `ifrs-full_ProfitLoss`, `dart_OperatingIncomeLoss` 또는 `ifrs-full_ProfitLossFromOperatingActivities`, `ifrs-full_CashFlowsFromUsedInOperatingActivities`.
   - 이때 `is_active=1` 조건을 붙인다.
9. **출처:** 답변에 `rcept_no`를 표시한다. 계산값은 `calculation_method`로 "계산값"임을 밝힌다.
