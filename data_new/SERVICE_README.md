# 현재 서비스의 데이터 연결과 분석 흐름

이 문서는 **2026-10-02에 확인한 코드와 실제 DB**를 기준으로 BOOTCAMP_MINI 화면이 만들어지는 과정을 설명합니다. 수집·표준화·임베딩에 관한 상류 프로젝트의 설명은 [README.md](README.md)에 있습니다. 그 문서의 `src.*` 명령과 macOS 경로는 현재 통합 프로젝트에서 그대로 실행할 수 있는 명령이 아닙니다.

현재 서비스는 이미 만들어진 DB를 읽습니다. 실행 과정에서 공시 전체를 다시 수집·청킹·임베딩하거나 이전 BGE-M3/Qdrant 파이프라인을 실행하지는 않습니다. 아래에서는 현재 구현과 향후 확장 방안을 구분합니다.

## 1. 자료와 파일의 역할

등록된 섹터는 반도체 하나이며, 대상 기업은 삼성전자·SK하이닉스·한미반도체·주성엔지니어링·원익IPS입니다. 실제 DB에서 확인한 범위는 다음과 같습니다. 수량은 자료를 교체하면 달라집니다.

| 자료 | 현재 확인한 내용 | 용도 |
| --- | --- | --- |
| `반도체/financial.db` | 2023-2025년, Q1·H1·Q3·FY, 연결재무(CFS); `financial_facts_final` 뷰 10,969행 | 재무 수치 조회와 지표 계산 |
| `반도체/filings.db` | 정기보고서 접수번호 60개, 청크 10,622개 | 공시 문구·출처·저장 벡터 검색 |
| `반도체/original/` | 접수번호별 XML 60개, `manifest.json` | 그래프 팝업의 전체 원문 표 |
| `service/반도체/reports.json` | 재무 이력, 워드클라우드, 인사이트, 각주 | 웹 화면에 제공하는 저장 보고서 |
| `service/market.json` | 종목 시세, KRX 지수, 대표 기업 시가총액 비중 등 | 시세 카드와 지표 가중평균 |

공시 벡터의 모델명은 `local-ko-en-finance-hashing-v1`, 차원은 1536이며 float32 BLOB으로 저장되어 있습니다. 현재 청크 본문의 관측 길이는 118-1,800글자입니다. 이는 현재 DB의 조회 결과이지 서비스가 적용하는 새 청킹 설정이 아닙니다.

```text
BOOTCAMP_MINI/
  snapdart_data/
    catalog.py              섹터 발견과 읽기 전용 DB 연결
    repository.py           재무 조회·계정 선택·공시 검색
    query.py                기업·기간·조회 종류 지정
    pipeline.py             계산·근거 선별·인사이트 생성·보고서 저장
    prompts.py              분석 지시문과 LLM 입력 형식
    sources.py              각주 발췌와 원문 표 조회
    xml_source.py           안전한 XML 읽기·표 병합 셀 복원
  data_new/
    README.md               제공된 데이터의 상류 처리 설명
    SERVICE_README.md       현재 서비스 연결 안내
    sectors.json            섹터 이름·기업 순서·검색어·단어 목록·소개
    반도체/
      financial.db
      filings.db
      original/             접수번호.xml, manifest.json
    service/
      market.json
      반도체/
        reports.json
        llm/                인사이트 응답 캐시
      llm/llm_errors/        응답 검증 실패 기록

  app.py                    로컬 HTTP 서버
  web/                      화면과 그래프
  snapdart/                 실행 명령·화면용 데이터·LLM/시세 통신
  data/krx_api/index_days.json  KRX 날짜별 조회 캐시
```

공시·재무 입력은 `data_new`의 DB이며 Qdrant를 사용하지 않습니다. **KRX 날짜별 캐시는 같은 프로젝트의 `data/krx_api`에 저장**되므로 모든 실행 파일이 `data_new`에만 있다고 설명하면 부정확합니다. 원문 표는 `snapdart_data/xml_source.py`에서 안전하게 읽고 복원하며, XML은 `data_new/<섹터>/original`에 있습니다. 과거 `dart_pipeline` 패키지와 그 전용 원본·가공·임베딩 자료는 폐기했습니다.

## 2. 보고서를 만드는 순서

### 2.1 섹터·기업·연도 선택

`catalog.py`는 `data_new` 바로 아래에서 DB 두 개가 모두 있는 폴더를 찾습니다. 폴더명이 섹터 ID이며 설정의 표시 이름과는 구분됩니다. 기업은 재무 DB의 `companies`에서 종목코드가 있는 행을 조회하고, `companies_order`와 종목코드 순으로 표시합니다.

분석 연도를 생략하면 `periods`에 있는 최근 3개년을 선택합니다. `--companies`와 `--years`는 게시 보고서의 범위를 바꾸며 원본 DB를 변경하지 않습니다.

### 2.2 재무 조회와 계산

서비스는 원장 `financial_facts`가 아니라 **`financial_facts_final` 뷰**를 조회합니다. 기업·연도·보고서·연결/별도 기준·기간 종류를 조건으로 지정합니다. FY의 기본 기간은 `annual`, Q1·H1·Q3는 `cumulative`이며 재고 같은 `point_in_time` 잔액도 함께 조회합니다. 분기 단독값은 별도 조회에서 `value_type=quarterly`로 지정할 수 있습니다.

현재 지표 선택은 매출·영업이익·영업활동현금흐름·재고·CAPEX 다섯 가지입니다. 표준 계정명과 일부 계정 ID, 재무제표 종류, KRW 조건으로 후보를 찾습니다. 후보 금액이 상충하면 오류를 내지만 DB 전체 계정의 회계적 타당성을 다시 검증하는 것은 아닙니다.

일반 지표는 `normalized_value` 또는 이미 계산된 `calculated_value`, CAPEX는 상류 DB가 직접 계정 또는 세부 계정 합계로 제공한 양수 `cash_outflow_amount`를 읽습니다. 서비스가 구성 계정을 다시 합산해 CAPEX를 새로 만드는 것은 아닙니다. 연간 재무는 CFS 행이 전혀 없을 때만 OFS로 재조회합니다. CFS의 특정 지표 하나가 누락됐다고 그 값만 OFS로 채우지는 않습니다.

Python은 전년 대비 변동률, 영업이익률, 매출 대비 CAPEX, 단순 FCF 등을 계산합니다. 변동률은 **선택된 이력에 직전 연도가 있고, 재무 기준이 같으며, 전년도 금액이 양수일 때** 계산합니다. 결측은 0으로 바꾸지 않습니다. 현재 DB에는 2022년을 직접 조회할 연간 레코드가 없어 기본 화면의 2023년 변동률은 비어 있습니다. 2024년부터 선택해 생성하면 2024년 변동률도 비어 있을 수 있습니다.

### 2.3 공시 근거 선별

인사이트는 섹터별 설정 검색어로 각 기업의 저장 보고서를 탐색합니다. 기본 선별은 `section_name`이 `II.` 또는 `IV.`로 시작하는 청크를 사용합니다. 사업의 내용과 경영진단 관련 섹션을 포함하지만, 청크의 중요성을 의미상 완전히 판별하는 기능은 아닙니다.

검색 결과에서 선택 연도만 남기고 최신 선택 연도는 기간마다 최대 2개 청크, 과거 연도는 최대 1개 청크를 사용합니다. 각 청크에서도 관련 검색어가 많은 30-320글자 문장 또는 줄 하나를 골라 LLM에 전달합니다. 조건에 맞는 발췌가 없으면 제외합니다.

분기·반기·3분기·사업보고서는 **모두 검색 후보**지만 모든 문서·문단이 분석에 포함되는 것은 아닙니다. 현재는 완성된 DB에서 근거를 선별하는 과정이며, 청크별 LLM 요약을 합치는 과거의 계층형 요약 파이프라인과도 다릅니다.

### 2.4 LLM 입력과 저장

재무 입력에는 선택 연도들의 연간 수치·계산 결과와 최신 선택 연도의 Q1·H1·Q3 누적 수치가 들어갑니다. 공시 입력에는 선별 발췌와 기업·기간·근거 ID가 들어갑니다. 공시 전체 XML이나 벡터를 LLM에 보내지는 않습니다.

산업 인사이트와 각 기업 인사이트는 별도 요청입니다. **AI 생성은 최신 선택 연도만** 수행합니다. 과거 연도에는 FY 공시 검색 발췌를 저장합니다. `--offline` 또는 LLM 옵션 없는 실행은 모든 연도를 발췌로 저장합니다. 현재 게시 파일에서도 2023·2024년은 발췌, 2025년은 AI 생성 결과입니다.

전체 보고서를 임시 파일에 쓴 뒤 `reports.json`으로 교체하며, 생성 도중 오류가 나면 기존 게시 파일을 교체하지 않습니다. 다만 웹 조회에서 DB·섹터 설정 변경을 감지하면 발췌 보고서를 자동 재생성할 수 있습니다. 기존 AI 보고서가 어떤 경우에도 항상 유지되는 것은 아닙니다.

## 3. 현재 벡터 검색의 실제 방식

상류 README는 단어·바이그램·문자 n-gram을 조합한 해시 임베딩으로 DB를 구축했다고 설명합니다. 현재 두 서비스 프로젝트에서 이 모델의 원래 질문 인코더 구현은 확인되지 않았습니다. 기존 `dart_pipeline/embed.py`의 BGE-M3는 다른 모델이므로 현재 저장 벡터의 질문 인코더로 사용하지 않습니다.

실제 `repository.py`는 다음 순서로 검색합니다.

1. SQL로 기업·연도·보고서를 제한합니다. 일반 검색은 기업·기간 조건을 생략할 수도 있으며, 인사이트 선별은 각 기업·기간을 지정합니다.
2. 질문에서 한글·영문 검색어와 코드에 정의된 소수의 별칭을 뽑습니다. 출현 횟수와 한글 비중으로 청크의 키워드 점수를 만듭니다.
3. 점수가 높은 최대 5개 청크의 **기존 벡터**를 가중평균해 검색 기준 벡터를 만듭니다.
4. 저장 벡터와의 코사인 유사도 55%, 정규화한 키워드 점수 45%를 결합해 순위를 정합니다. 최종 결과에도 키워드 점수가 있는 청크만 남깁니다.

키워드가 하나도 맞지 않으면 근거 없음으로 반환합니다. 질문을 원래 모델로 직접 임베딩하는 방식이 아니므로, 표현이 완전히 다른 문서를 의미만으로 찾는 검색이라고 설명해서는 안 됩니다. 범위 내 벡터를 비교하는 NumPy 연산과 메모리 캐시를 사용하며 Qdrant·ANN 인덱스를 호출하지 않습니다.

코드는 모델·차원 혼합, BLOB 차원 불일치, NaN·무한대 값을 검사합니다. **0벡터를 별도로 거절하는 검증은 현재 없습니다.** 이번 조회에서는 벡터 길이가 대략 1이고 0벡터가 없었습니다. 실제 데이터 상태와 구현된 검사 범위는 구분해야 합니다.

## 4. 프롬프트·검증·캐시

화면 인사이트는 `snapdart_data/prompts.py`의 공통 지시문과 산업·기업 지시문을 사용합니다. `snapdart/llm.py`는 모델 전송·토큰 예산·재시도를 담당하며 별도의 분석 지시문을 덧붙이지 않습니다. 입력에 없는 사실·수치·원인을 생성하지 않기, 단일 기업 현상의 산업 전체 일반화 방지, 자료 부족·상충 설명, 쉬운 표현과 매매 추천 금지가 정의서의 공통 규칙입니다.

산업 인사이트의 공통·개별 지시문과 사용자 요청은 프롬프트 정의서의 문구를 옮겨 사용합니다. 공통 흐름이 없으면 기업별 차이를 설명하고, 근거가 부족하면 그 한계를 표시하도록 지시합니다. 두 기업명·두 기업 근거·400자 제한은 없습니다. 문장별 수치 2개＋공시 1개 조건도 없으며, 출처 수의 최소·최대 제한을 두지 않습니다. PDF가 미정으로 둔 기업 인사이트에는 별도의 문장 수 상한을 두지 않습니다. PDF가 미정으로 둔 기업 전용 지시문은 PDF에 기재된 기업 분석 목적을 사용합니다. 화면의 기존 문장별 각주를 유지하기 위해 출력은 `sentences`의 `text`와 `refs`를 사용하며, 이는 PDF의 단일 `industry_insight` 필드와 다른 전송 구조입니다. 키워드 인사이트는 PDF 지시문을 사용하지만 화면·CLI·HTTP에 전용 호출 경로는 없습니다.

검증은 문장 수·빈 문장 여부·근거 ID와 일부 원화 금액의 근거 일치를 확인합니다. 기업명 개수와 특정 인과 표현을 기준으로 거절하지 않습니다. **문장 전체의 의미가 인용문에서 논리적으로 따라 나오는지까지 자동 검증하지는 않습니다.** 재무 근거 ID는 연간 수치와 제공된 Q1·H1·Q3 누적 수치에 각각 부여합니다. 중간 보고서 각주는 해당 보고서의 수치와 접수번호를 사용하며 연간 수치로 잘못 연결하지 않습니다. 문장별 출처 개수와 종류별 배분을 강제하지 않습니다. 자료 부족 설명의 빈 출처 배열도 허용하며, 금액 검사는 입력 부호와 표시 단위의 반올림 정밀도를 확인합니다.

Gemini 인사이트 요청은 temperature 1, 최대 출력 500토큰이며 내부 키워드 분기는 300토큰입니다. 이는 출력 상한이지 입력 크기나 모든 실행의 설정이 아닙니다. Ollama도 전달된 temperature와 출력 상한을 따릅니다. 출력 예산은 요청 상한과 `OLLAMA_NUM_PREDICT` 중 작은 값이며, 문맥·배치·GPU 설정은 기존 로컬 환경변수를 사용합니다.

Gemini는 `countTokens`로 입력 토큰을 확인하고 프로세스 내부에서 TPM·RPM 예산을 지키며 대기합니다. 기본 예산은 TPM 225,000, RPM 10이며 환경변수로 변경할 수 있습니다. Google의 실제 한도를 조회한 값이 아니고 다른 실행 프로세스와 사용량도 공유하지 않습니다. 단일 요청이 예산을 넘으면 중단하며 입력을 자동 재분할하지는 않습니다. 일시적 통신 오류는 최대 3회 시도하고 응답 검증 실패는 한 차례 교정 요청을 합니다. 모든 API 오류를 예방하는 장치는 아닙니다.

인사이트 응답 캐시는 프롬프트 버전·지시문·입력·모델·제공자로 구분합니다. `--llm`도 유효한 캐시를 재사용하고 `--refresh-llm`은 재사용하지 않습니다. 게시 보고서 변경 감지는 DB 파일 크기·수정 시각, 섹터 설정, 고정 코드 버전 문자열을 사용합니다. DB 전체 내용의 해시 검사나 프롬프트 파일 수정 자동 감지는 아니므로, 프롬프트 변경 후에는 명시적으로 재생성해야 합니다.

## 5. 화면의 지표·워드클라우드·출처

핵심 그래프는 연간 매출·영업이익·CAPEX·영업활동현금흐름의 변동률입니다. 상단 수치는 최신 선택 연도이며 산업 화면은 **유효한 기업별 변동률을 대표 기업 시가총액 비중으로 가중평균**합니다. 수치나 비중이 빠진 기업은 제외하고 남은 비중을 다시 맞춥니다. 공식 KRX 구성 비중이나 산업 전체 지표의 증가율은 아닙니다. 비중은 시세 스냅샷 기준이며 연도별 과거 비중이 아닙니다.

워드클라우드는 선택 연도의 모든 보고서 유형에서 `II. 사업…` 섹션 청크의 **지정 용어** 횟수를 셉니다. 형태소 분석으로 모든 단어를 추출하는 방식이 아닙니다. 청크·문서 사이의 중복을 제거하지 않으며 `투자`와 `설비투자`처럼 포함 관계인 용어도 각각 셀 수 있습니다. 빈도는 사업 변화나 실적 개선의 강도가 아닙니다.

출처 창에는 두 가지 경로가 있습니다.

- **공시 각주:** `chunk_id`로 DB 청크를 읽고 인용 문자열과 청크 내부 문자 위치의 일치를 확인합니다. 인접 청크도 표시합니다. 원문 PDF 페이지나 원래 문단 번호를 찾아 표시하는 기능은 아닙니다.
- **그래프 공시 버튼:** 접수번호 XML에서 계정명·당기 금액·단위를 대조해 전체 표를 표시합니다. CAPEX 파생 합계는 구성 항목 셀을 함께 강조합니다. 재무 인사이트 각주는 표준화 수치 발췌와 확인 가능한 매출 원문 표를 보여주지만, 모든 서술 지표의 표를 자동으로 골라 주는 구조는 아닙니다.

XML이 없거나 대조 가능한 표를 찾지 못하면 원문 표를 제공할 수 없습니다. 표 파싱에서는 텍스트 보존 검사를 하지만 `manifest.json`의 해시를 실행 때마다 대조하는 코드는 없습니다. 청크 출처 확인, 원문 표 대조, 원본 파일 무결성 검증은 서로 다른 기능입니다.

## 6. 시세와 최신 공시의 별도 갱신

개별 주가는 FinanceDataReader의 NAVER 데이터, 시가총액은 NAVER 응답으로 조회합니다. **KRX 반도체 지수는 FinanceDataReader로 직접 받지 않고 `KRX_API` 인증키로 공식 API를 호출**합니다. 시세는 실행일 당일을 제외한 가장 최근 저장 거래일 종가와 그 직전 거래일을 비교합니다. 갱신 실패 시 이전 자료를 유지할 수 있어 표시 거래일과 갱신 상태를 함께 확인해야 합니다.

`app.py`는 기본 실행에서 시세를 갱신하지만 LLM이나 분석 DB를 갱신하지 않습니다. `--no-market-refresh`는 외부 시세 조회도 생략합니다. 별도 `python -m snapdart.market`는 시세와 최근 90일 DART 목록을 갱신하지만 새 공시 본문을 DB에 적재하거나 인사이트를 재생성하지는 않습니다. 시세 조회일이 최신이라고 분석 대상 공시도 최신인 것은 아닙니다.

## 7. 실행 방법

통합 폴더의 Python 3.12 가상환경을 활성화한 PowerShell에서 실행합니다: `.\.venv\Scripts\Activate.ps1`. 활성화하지 않으면 `python` 대신 `.\.venv\Scripts\python.exe`를 사용합니다. 벡터 조회에는 `numpy`, 시세 수집에는 `pandas`와 `finance-datareader`가 필요합니다.

기존 보고서와 저장 시세만 확인할 때:

```powershell
cd C:\Users\LSH\Downloads\Code\BOOTCAMP_MINI
python -X utf8 app.py --no-market-refresh
```

기본 주소는 `http://127.0.0.1:8501`입니다. 시세 갱신도 시도하려면 옵션을 생략합니다. 서버 시작 자체는 기존 AI 인사이트를 다시 생성하지 않습니다.

Gemini로 최신 선택 연도 인사이트를 생성할 때:

```powershell
$env:LLM_PROVIDER = "gemini"
python -X utf8 -m snapdart.analyze --llm --sector 반도체
# 응답 캐시까지 무시하려면 --llm 대신 --refresh-llm 사용
```

API 없이 발췌 보고서를 다시 만들 때:

```powershell
python -X utf8 -m snapdart.analyze --offline --sector 반도체
```

이 명령은 기존 AI 보고서를 발췌 보고서로 교체합니다. LLM 옵션 없이 `snapdart.analyze`만 실행해도 발췌를 생성합니다. 기존 AI 결과를 유지하려면 분석 명령 없이 앱만 실행합니다.

`load_env()`는 프로세스 환경변수를 우선하며, 통합 프로젝트 루트의 `.env` 하나를 읽습니다. Gemini는 `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY`, 지수 수집은 `KRX_API`를 사용합니다. 경로를 바꾸려면 모듈을 읽기 전에 PowerShell에서 `SNAPDART_DATA_ROOT`를 지정합니다. 기본 섹터는 `SNAPDART_SECTOR`, 공통 모듈과 웹 서버는 같은 루트에 있으므로 `SNAPDART_PIPELINE_ROOT`는 사용하지 않습니다. `--sector`는 분석·조회 범위이며 시세 수집기의 모든 설정을 전환하지는 않습니다.

범위 지정 조회 예시:

```powershell
python -X utf8 -m snapdart.query --sector 반도체 --company SK하이닉스 --year 2025 --report-type FY --intent hybrid --question "HBM 수요와 투자 변화"
python -X utf8 -m snapdart.query --sector 반도체 --company 주성엔지니어링 --year 2024 --report-type H1 --value-type quarterly --intent financial --question "설비투자 금액"
```

`--intent`는 사용자가 financial·filing·hybrid 중 지정하며 기본은 hybrid입니다. 질문을 자동 분류하거나 임의 계정을 고르는 SQL 생성기는 없습니다. 재무 경로는 구현된 다섯 지표를 반환합니다. 기본 조회는 근거만 출력하며 `--llm`을 추가해야 답변을 요청합니다. SQL 조건은 코드가 바인딩하고 LLM은 SQL을 실행하지 않습니다.

HTTP 경로는 `/api/sectors`, `/api/reports`, `/api/financial`, `/api/search`, `/api/source`, `/api/revenue-source`입니다. 마지막 경로는 이름과 달리 `key=revenue|operating_income|capex|operating_cashflow`로 네 지표의 표를 조회합니다. 검색·재무·출처 요청에는 `sector`를 전달하며 `/api/source`의 `ref`는 게시 보고서에 등록된 각주 ID여야 합니다.

## 8. 새 산업·기업을 추가할 때의 지원 범위

동일 스키마의 DB 두 개를 새 섹터 폴더에 두면 섹터·기업을 발견하고 같은 조회 경로를 사용합니다. 그러나 파일명만 맞으면 임의 데이터가 모두 동작하는 것은 아닙니다. 테이블·뷰·필수 열, 기업코드 일치, 보고서 유형, 벡터 형식, 계정 매핑을 맞춰야 합니다. 12월 결산·원화 재무·국내 종목 시세를 전제로 한 기간 표시와 수집 경로도 확인해야 합니다.

검색어·용어·기업 소개는 `sectors.json`, 계정 체계가 다른 산업의 지표 매핑은 `repository.py`에서 검토합니다. 원문 표 기능에는 XML도 필요합니다. ANN 검색, 새 질문의 직접 임베딩, 키워드 팝업, 질문 의도 자동 분류는 향후 확장 방향이며 현재 완성된 기능이 아닙니다.

특히 **시세 수집기는 현재 KRX 반도체 대상으로 고정**되어 있습니다. `index_code` 설정만 바꿔 새 지수를 자동 수집하지 않습니다. 화면은 지수 코드가 `5044`면 공통 `service/market.json`, 그 외에는 `service/<섹터>/market.json`을 읽습니다. 다른 산업의 시세·지수·비중을 자동 갱신하려면 해당 경로에 맞는 수집기를 추가하거나 기존 수집기를 일반화해야 합니다.

## 9. 확인 근거

직접 근거는 `snapdart_data`와 `snapdart`의 `analyze.py`, `query.py`, `dashboard.py`, `market.py`, `krx_api.py`, `llm.py`, `local_llm.py`, `web/app.js`입니다. 프롬프트 버전은 `bigin-pdf-v4`입니다. 이 변경은 기존 게시 보고서를 자동 교체하지 않으며 명시적 재생성이 필요합니다.

DB 연결은 `mode=ro`와 `PRAGMA query_only=ON`을 사용합니다. 읽기 전용 URI 옵션의 의미는 [SQLite 공식 문서](https://www.sqlite.org/uri.html)에 설명되어 있습니다.
